## 1. 改造结论

第三版不再从Markdown章节和部署验证记录重新生成。新的工作方式是：复制《云计算基础架构平台构建与应用（第二版初稿）.docx》，将复制件作为唯一正文母稿，在第二版原有段落、图片位置、章节顺序和版式基础上进行更新。

第二版原文件保持只读，不直接修改。当前已经生成的第三版初稿不再作为正文底稿，只作为以下技术事实的参考资料：

- openEuler 24.03 LTS SP3双节点环境参数；
- OpenStack 2023.1 Antelope软件包、服务和配置项；
- controller与compute的部署顺序；
- 已经实测的命令、配置值和组件依赖；
- Cinder、Swift、Horizon及智能体章节的素材来源。

部署测试记录、验证器、审计报告和自动化程序不进入第二篇教材正文。

## 3. 第二版风格冻结

### 3.1 页面和字体

- 页面尺寸：18.4 cm × 26 cm；
- 上、下、左、右页边距：均为2 cm；
- 页眉距离1.5 cm，页脚距离1.75 cm；
- 正文：宋体10.5磅，两端对齐，首行缩进约2个中文字符；
- 一级标题：22磅加粗；
- 二级、三级标题：16磅加粗；
- 图注：宋体9磅、加粗、居中；
- 命令与配置：沿用正文等字号可编辑文字，不使用灰底代码框；
- 图片常规宽度12—14.4 cm，局部图片8—12 cm，居中排版。

不得沿用上一版第三稿自行设计的蓝色标题、窄页边距、密集三级标题和灰底代码块。

所有命令行必须保留其所在环境的系统提示符，与第二版一致，不允许只写裸命令：

- controller的root命令：`[root@controller ~]# dnf -y install ...`
- compute的root命令：`[root@compute ~]# vi /etc/nova/nova.conf`
- 普通Linux用户命令：使用该用户实际的`$`提示符；
- MariaDB登录后的命令：`MariaDB [(none)]> CREATE DATABASE keystone;`
- 选择数据库后的命令：`MariaDB [keystone]> SHOW TABLES;`
- MariaDB续行使用客户端实际显示的`->`提示符。

多行Shell命令第一行必须带完整主机提示符，后续续行按照终端实际的反斜杠换行形式缩进。`vi`打开文件的Shell命令带主机提示符；进入编辑器后列出的配置文件正文不添加Shell提示符。

### 3.2 章节语言

保持第二版“教师带领学生学习和操作”的语言风格，使用完整的原因、过渡和结果说明。常用叙事方式包括“本章介绍……”“下面我们……”“首先……”“接着……”“最后……”。

理论内容采用连续讲解，不改写为资料摘要或概念清单。组件内容先说明背景、作用、架构、主要对象和调用关系，再进入实训。

### 3.3 章节和实训骨架

章节继续采用：

1. 本章导读；
2. 功能或原理介绍；
3. 实训项目；
4. 必要的图示、命令、参数解释和操作界面。

每个实训项目继续采用：

1. 一．实训前提环境；
2. 二．实训涉及节点；
3. 三．实训目标或实训要求；
4. 四．实训步骤及其详解。

不得把每章统一改成“学习目标—若干三级知识点—小结—习题”的模板化结构。

## 5. 分部分改造方法

### 5.1 云计算产业与OpenStack概览

第一章保留“计算模式演变—云计算定义—服务层次与分类—产业发展”的认识过程。过时产业数据、政策、企业产品和技术趋势更新到2026年7月，并增加云原生、边缘云、智算云、FinOps、绿色云、主权云和可信云等内容。

第二章保留国内外厂商和产品的比较框架，更新仍在发展的产品，删除已经失去代表性的旧界面和陈旧结论。资料需消化成教材叙事，不把官方链接和来源清单直接堆在正文。

第三章保留OpenStack起源、架构、核心组件和平台体验流程，扩展基金会与社区治理、核心服务、扩展生态、版本演进和2026.1概览。各组件继续采用一组件一段说明与架构图配合的方式。

### 5.2 openEuler与信创环境

第四章用openEuler 24.03 LTS SP3替换CentOS环境，增加openEuler发展、技术特点、软硬件生态、社区、信创应用和软件源的小节。终端工具只用一小段说明可以选择Xshell、SecureCRT或Windows PowerShell，删除第二版原有的大篇幅终端工具教学。

环境配置继续按第二版实训项目结构讲解虚拟机、主机名、网络、hosts、时间同步和本地软件源。所有IP、网卡和磁盘参数改为本书双节点环境。

### 5.3 OpenStack组件部署

组件章保留第二版“功能介绍—实训项目”的结构和原理讲解。各步骤采用以下固定节奏：

1. 说明为什么需要该操作；
2. 明确在controller或compute节点执行；
3. 给出一条或一组Linux命令；
4. 使用`vi`打开配置文件；
5. 展示需要写入或修改的完整配置节；
6. 逐项解释关键参数；
7. 完成数据库同步、身份对象、服务和端点创建；
8. 启用并启动服务，结束该组件部署。

安装过程使用DNF和Linux命令行，不出现任何Python程序、Python heredoc、Paramiko、测试框架或远程执行器。

配置文件修改以`vi`为唯一教学主线，不使用`crudini`代替学生编辑过程。

每条Linux、MariaDB或OpenStack客户端命令均须带第二版同类系统提示符。不得使用Markdown式无提示符代码块替代真实教材命令行。

数据库、用户、角色授权、服务和public/internal/admin三类端点的创建步骤及解释必须保留。

### 5.4 “只部署、不验证”边界

安装部署章允许：

- 安装软件包；
- 创建数据库与数据库用户并授权；
- 手工编辑配置文件；
- 手工同步数据库；
- 创建OpenStack用户、角色授权、服务和三类端点；
- 初始化Fernet、Cell、Ring、LVM或XFS等部署必需对象；
- 启用并启动服务。

安装部署章不写：

- API、端口、服务状态或数据库表验证；
- 测试镜像、测试实例、测试卷、测试容器或对象；
- 测试资源清理；
- 失败即停门禁、证据、审计、验收报告；
- 回滚程序、备份时间戳和故障注入；
- Shell函数、循环、条件判断、一键安装程序；
- Python及任何Python相关执行内容。

原“安装脚本及其解读”全部从第二篇删除。`openstack-ts`只作为作者核对新版命令和配置的技术参考，不作为学生安装方法。

### 5.5 手工运维迁移

原第十三章运维流程整体迁移到新信创云平台，保持“先解释对象和场景—给出命令—解释参数和字段—配Dashboard界面”的教学方式。

- Neutron网络、子网、路由器、安全组和浮动IP；

- 新增Swift容器和对象管理；
- Horizon中与命令行任务对应的界面操作。

运维命令属于教学内容，不按安装验证删除。流程保持第二版顺序，只替换为Antelope兼容命令和新版真实界面。

### 5.6 智能体部分

## 8. 编辑实现方式

1. 复制第二版DOCX为新的第三版工作母稿；
2. 原文件只读保存并记录SHA-256；
3. 使用第二版原有Word样式、节设置、页眉页脚和图片锚点；
4. 按章和段落范围定点替换，不从Markdown重新生成整书；

7. 使用Word重新分页和更新目录；
8. 输出第三版DOCX、PDF校样、独立图片目录和配套环境目录。
