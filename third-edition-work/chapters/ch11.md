# 第11章 Horizon、平台初始化与综合运维

## 学习目标

手工安装 Horizon，用 `vi` 配置 `/dashboard/`、Keystone v3、Memcached 与时区；逐条命令初始化项目、用户、配额、镜像、规格、网络、路由、安全组、密钥、实例、浮动 IP、卷、Swift 对象和快照；建立巡检、排错与按依赖反向清理的完整人工运维流程。本章所有命令由学生手工输入，与第13章的智能体任务化运维明确分轨。

## 11.1 Horizon仪表板

### 11.1.1 Horizon架构和访问路径

Horizon 是运行在 Apache/mod_wsgi 上的 Django 应用，通过 Keystone 获取令牌与服务目录，再调用 Nova、Neutron、Glance、Cinder、Swift API。本实验访问路径为 `http://controller/dashboard/`。

### 11.1.2 安装软件包并备份默认配置

```bash
dnf -y --disablerepo='*' --enablerepo=openstack-local --setopt=install_weak_deps=False install openstack-dashboard
umask 077; backup=/root/openstack-lab-backups/horizon-$(date -u +%Y%m%dT%H%M%SZ)
install -d -m 0700 "$backup"
cp -a /etc/openstack-dashboard/local_settings /etc/httpd/conf.d/openstack-dashboard.conf "$backup"/
```

### 11.1.3 使用vi编辑local_settings

```bash
vi /etc/openstack-dashboard/local_settings
```

```python
ALLOWED_HOSTS = ['controller', '192.168.234.151', 'localhost', '127.0.0.1']
OPENSTACK_HOST = 'controller'
OPENSTACK_KEYSTONE_URL = 'http://%s:5000/v3' % OPENSTACK_HOST
OPENSTACK_KEYSTONE_MULTIDOMAIN_SUPPORT = True
OPENSTACK_KEYSTONE_DEFAULT_DOMAIN = 'Default'
OPENSTACK_KEYSTONE_DEFAULT_ROLE = 'member'
OPENSTACK_API_VERSIONS = {'identity': 3, 'image': 2, 'volume': 3}
WEBROOT = '/dashboard/'
LOGIN_URL = '/dashboard/auth/login/'
LOGOUT_URL = '/dashboard/auth/logout/'
LOGIN_REDIRECT_URL = '/dashboard/'
TIME_ZONE = 'Asia/Shanghai'
SESSION_ENGINE = 'django.contrib.sessions.backends.cache'
CACHES = {'default': {'BACKEND': 'django.core.cache.backends.memcached.PyMemcacheCache',
                      'LOCATION': 'controller:11211'}}
```

保留包生成的 `SECRET_KEY`，不显示、哈希或复制。

### 11.1.4 重启Apache并完成/dashboard/登录验证

```bash
chown root:apache /etc/openstack-dashboard/local_settings; chmod 0640 /etc/openstack-dashboard/local_settings
httpd -t
python3 /usr/share/openstack-dashboard/manage.py check
systemctl enable httpd; systemctl restart httpd
curl --noproxy '*' -I http://controller/dashboard/
curl --noproxy '*' -sS http://controller/dashboard/auth/login/ | grep -E 'username|password|csrfmiddlewaretoken'
```

根路径应302跳转到 `/dashboard/auth/login/?next=/dashboard/`，登录页应200并含表单与 CSRF 标记。手工浏览器登录后验证 Overview 并注销，不导出 Cookie、令牌或密码。

## 11.2 项目、用户、角色与配额

### 11.2.1 手工创建项目、用户与角色授权

```bash
source /root/admin-openrc
openstack project create --domain Default training
openstack user create --domain Default --password-prompt student
openstack role add --project training --user student member
openstack role assignment list --project training --user student --names
```

### 11.2.2 设置并核对项目配额

```bash
project_id=$(openstack project show training -f value -c id)
openstack quota set --instances 4 --cores 8 --ram 8192 --volumes 4 --gigabytes 20 "$project_id"
openstack quota show "$project_id"
```

### 11.2.3 CLI与Horizon操作对照

| 表11-1　操作对照 | CLI | Horizon |
| --- | --- | --- |
| 创建项目/用户 | `openstack project/user create` | Identity |
| 配额 | `openstack quota set/show` | Project→Compute→Overview |
| 资源详情 | `openstack ... show` | 相应资源详情页 |

CLI 便于精确记录和复现，Horizon 便于理解状态与拓扑；两者调用同一 API。

## 11.4 网络、安全组与密钥对

### 11.4.1 创建Provider网络和租户网络

```bash
openstack network create --external --share --provider-network-type flat \
  --provider-physical-network provider provider
openstack subnet create --network provider --subnet-range <PROVIDER_CIDR> --no-dhcp \
  --gateway <PROVIDER_GATEWAY> --allocation-pool start=<START_IP>,end=<END_IP> provider-subnet
openstack network create training-net
```

### 11.4.2 创建子网和路由器

```bash
openstack subnet create --network training-net --subnet-range 172.16.10.0/24 \
  --gateway 172.16.10.1 --dns-nameserver <DNS_IP> training-subnet
openstack router create training-router
openstack router add subnet training-router training-subnet
openstack router set training-router --external-gateway provider
```

### 11.4.3 配置安全组规则

```bash
openstack security group create training-secgroup
openstack security group rule create --protocol icmp training-secgroup
openstack security group rule create --protocol tcp --dst-port 22:22 training-secgroup
openstack security group rule list training-secgroup
```

### 11.4.4 创建和保护密钥对

```bash
umask 077
openstack keypair create training-key >training-key.pem
chmod 0600 training-key.pem
openstack keypair show training-key
```

私钥只在首次创建时返回，不纳入版本库或截图。

## 11.5 实例与浮动IP

### 11.5.1 启动并观察实例调度

```bash
server_id=$(openstack server create --image CirrOS --flavor m1.tiny --network training-net \
  --security-group training-secgroup --key-name training-key vm01 -f value -c id)
openstack server show "$server_id"
openstack hypervisor list --long
```

### 11.5.2 查看控制台与实例日志

```bash
openstack console url show "$server_id"
openstack console log show "$server_id"
```

### 11.5.3 分配、绑定并验证浮动IP

```bash
floating_ip=$(openstack floating ip create provider -f value -c floating_ip_address)
openstack server add floating ip "$server_id" "$floating_ip"
openstack server show "$server_id" -c addresses
ping -c 4 "$floating_ip"
```

## 11.6 块存储与对象存储运维

### 11.6.1 创建、挂载、卸载和删除卷

```bash
volume_id=$(openstack volume create --size 1 --type lvm data01 -f value -c id)
openstack server add volume "$server_id" "$volume_id"
openstack volume show "$volume_id"
openstack server remove volume "$server_id" "$volume_id"
openstack volume delete "$volume_id"
```

### 11.6.2 创建Swift容器并管理对象

```bash
echo 'OpenStack training object' >object.txt
openstack container create training-container
openstack object create training-container object.txt
openstack object save training-container object.txt --file object.download
sha256sum object.txt object.download
```

### 11.6.3 资源状态与数据一致性核验

卷在挂载前应 `available`，挂载后 `in-use`，卸载后回到 `available`；Swift 上传与下载文件摘要应一致。不在后端手工删 LV 或 Swift 对象文件。

## 11.7 快照与资源生命周期

### 11.7.1 创建实例快照并重建实例

```bash
snapshot_id=$(openstack server image create --name vm01-snapshot "$server_id" -f value -c id)
openstack image show "$snapshot_id"
openstack server create --image "$snapshot_id" --flavor m1.tiny --network training-net \
  --security-group training-secgroup --key-name training-key vm01-rebuilt
```

### 11.7.2 调整、迁移和按依赖顺序清理资源

单计算节点环境可练习 `server resize`，不宣称已验证跨主机迁移。清理顺序为：浮动IP解绑/删除→卷卸载/删除→实例→快照→路由器接口/网关→子网/网络→安全组/密钥→Swift对象/容器→规格/项目。每项都先 `show/list`确认 ID，不使用名称通配删除。

## 11.8 平台巡检与典型故障

### 11.8.1 服务、端点、Agent与后端巡检

```bash
source /root/admin-openrc
openstack service list; openstack endpoint list --region RegionOne --long
openstack compute service list; openstack hypervisor list
openstack network agent list
openstack volume service list; openstack volume backend pool list
curl --noproxy '*' -fsS http://controller:8080/healthcheck
systemctl --failed
```

### 11.8.2 时间、RabbitMQ、主机发现与Linux Bridge故障

令牌间歇失败先看 `chronyc tracking`；多服务同时 down 查 RabbitMQ；compute up 但无 hypervisor 查 `discover_hosts`；虚拟机无网查 Agent、`provider:ens34`、VXLAN `local_ip`、bridge 和 namespace。

### 11.8.3 Horizon WEBROOT与登录故障

404检查 `WEBROOT` 和 Apache `WSGIScriptAlias`；重定向循环检查 LOGIN/LOGOUT/REDIRECT URL；登录失败分别验证 Keystone CLI、Default 域、member 角色和 Memcached，不应先删用户。
