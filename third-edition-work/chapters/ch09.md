# 第9章 Neutron网络服务

## 学习目标

理解 Neutron Server、ML2、Linux Bridge、DHCP、L3、Metadata Agent 的协作；区分 Provider 网络与 VXLAN 租户网络；手工完成 Neutron 建库与三 Host 授权、身份/服务/三端点、控制与计算节点全部配置、数据库同步和服务启动；创建 Provider 和租户网络，验证 Agent、网桥、命名空间与 Metadata 路径。

## 9.1 Neutron架构与网络模型

### 9.1.1 Neutron Server、插件与Agent

Neutron Server 提供 9696 API并持久化逻辑网络。ML2 把网络类型与实现机制分离；本实验使用 flat、VXLAN 类型驱动和 Linux Bridge 机制驱动。Linux Bridge Agent 运行于两节点；DHCP、L3、Metadata Agent 运行于 controller。

### 9.1.2 Provider网络与租户网络

Provider 网络通过 `provider:ens34` 映射与实验室外部二层网相连，ens34 本身不配 IP。租户网络使用 VXLAN，controller 的 tunnel endpoint 是 `.151`，compute 是 `.150`，VNI 范围 `1:1000`。

### 9.1.3 二层、三层、DHCP与Metadata数据流

二层 Agent 建立 bridge/tap/VXLAN；DHCP 命名空间为实例分配地址；L3 命名空间在租户网与外部网之间路由/NAT；Metadata Agent 与 Nova metadata 共享密钥。图9.1建议绘制“实例tap—Linux bridge—VXLAN/ens34”链路。

## 9.3 手工配置ML2插件

### 9.3.1 安装软件包并建立插件链接

```bash
ln -s /etc/neutron/plugins/ml2/ml2_conf.ini /etc/neutron/plugin.ini
vi /etc/neutron/neutron.conf
```

### 9.3.2 使用vi配置neutron.conf

```ini
[DEFAULT]
core_plugin = ml2
service_plugins = router
transport_url = rabbit://openstack:<URL_ENCODED_PASSWORD>@controller
auth_strategy = keystone
notify_nova_on_port_status_changes = true
notify_nova_on_port_data_changes = true
[database]
connection = mysql+pymysql://neutron:<URL_ENCODED_DB_PASSWORD>@127.0.0.1/neutron
[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = neutron
password = <SERVICE_PASSWORD>
[nova]
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
region_name = RegionOne
project_name = service
username = nova
password = <SERVICE_PASSWORD>
[oslo_concurrency]
lock_path = /var/lib/neutron/tmp
[experimental]
linuxbridge = true
```

### 9.3.3 配置flat、VXLAN与VNI范围

```bash
vi /etc/neutron/plugins/ml2/ml2_conf.ini
```

```ini
[ml2]
type_drivers = flat,vxlan
tenant_network_types = vxlan
mechanism_drivers = linuxbridge,l2population
extension_drivers = port_security
[ml2_type_flat]
flat_networks = provider
[ml2_type_vxlan]
vni_ranges = 1:1000
[securitygroup]
enable_ipset = true
```

### 9.3.4 配置Linux Bridge实验开关

Antelope 包将 Linux Bridge 机制标记为 experimental，因此两节点均需 `[experimental] linuxbridge=true`。这是为了教学展示 Linux 网桥，不是对生产网络方案的推荐。

## 9.4 手工配置控制节点Agent

### 9.4.1 配置Linux Bridge Agent与provider:ens34

```bash
vi /etc/neutron/plugins/ml2/linuxbridge_agent.ini
```

```ini
[linux_bridge]
physical_interface_mappings = provider:ens34
[vxlan]
enable_vxlan = true
local_ip = 192.168.234.151
l2_population = true
[securitygroup]
enable_security_group = true
firewall_driver = neutron.agent.linux.iptables_firewall.IptablesFirewallDriver
```

### 9.4.2 配置DHCP Agent

```bash
vi /etc/neutron/dhcp_agent.ini
```

```ini
[DEFAULT]
interface_driver = linuxbridge
dhcp_driver = neutron.agent.linux.dhcp.Dnsmasq
enable_isolated_metadata = true
```

### 9.4.3 配置L3 Agent

```bash
vi /etc/neutron/l3_agent.ini
```

```ini
[DEFAULT]
interface_driver = linuxbridge
```

### 9.4.4 配置Metadata Agent与Nova联动

```bash
vi /etc/neutron/metadata_agent.ini
```

```ini
[DEFAULT]
nova_metadata_host = controller
metadata_proxy_shared_secret = <SERVICE_PASSWORD>
```

```bash
cat >/etc/sysctl.d/99-openstack-neutron.conf <<'EOF'
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF
modprobe br_netfilter
sysctl --system
```

## 9.9 网络验收与故障排查

### 9.9.1 服务、API和Agent轻量验收

controller五项Neutron服务与compute Linux bridge Agent 应 `active/enabled`；9696 API、认证 `openstack network list` 成功；Agent 列表中 controller/compute 的 Linux bridge 以及 DHCP、L3、Metadata 都 Alive。创建一个临时 internal network，查询后按精确 ID 删除，即可证明最小数据路径。

### 9.9.2 Provider映射、VXLAN和命名空间故障

- Provider不通：核对 `provider:ens34`、ens34无IP、实验室交换机/VLAN。
- VXLAN不通：核对两节点 `local_ip`、VNI范围、bridge netfilter。
- Agent down：查对应 `systemctl`/`journalctl`，不用创建更多网络掩盖。
- Metadata失败：核对两端 shared secret、Nova `[neutron]` 和 metadata namespace。
