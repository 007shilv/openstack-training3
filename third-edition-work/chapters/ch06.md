# 第6章 Keystone身份认证服务

## 学习目标

完成本章后，应能区分域、项目、用户、角色、服务和端点；说明 Keystone 令牌和服务目录的作用；在 controller 手工创建 Keystone 数据库及三个 Host 授权；用 `vi` 完成配置，手工同步数据库、初始化 Fernet/Credential 密钥、bootstrap 身份服务；创建 service 项目并使用 OpenRC、API 和 CLI 验证。

## 6.1 Keystone架构与认证流程

### 6.1.1 域、项目、用户与角色

域（Domain）是项目、用户和组的命名与管理边界；项目（Project）是计算、网络和存储资源的所有与配额边界；用户是认证主体；角色描述权限名称。“将某角色赋予某用户于某项目”才形成有效授权。本书使用 Default 域，`admin` 管理项目和 `service` 服务项目。

### 6.1.2 服务、Region与三类端点

服务目录记录云平台提供的 API。每项服务在 RegionOne 中注册 public、internal、admin 三类端点。三者可以有不同网络路径，本双节点实验为便于学习而指向同一 URL。如图6.1所示，用户先向 Keystone 申请令牌和服务目录，再持令牌访问其他组件。

### 6.1.3 Token签发和服务访问流程

Antelope 默认使用 Fernet 令牌。Fernet 令牌不需要在数据库逐条保存，但所有 Keystone 节点必须保持密钥一致。Credential 密钥用于保护凭据数据。密钥文件的权限、备份和轮换是身份平面安全的核心。

### 6.2.3 手工创建三条数据库用户和最小授权

将占位符替换为实训口令，不得把尖括号原样输入：

```sql
CREATE USER 'keystone'@'localhost' IDENTIFIED BY '<DB_PASSWORD>';
CREATE USER 'keystone'@'127.0.0.1' IDENTIFIED BY '<DB_PASSWORD>';
CREATE USER 'keystone'@'%' IDENTIFIED BY '<DB_PASSWORD>';
GRANT ALL PRIVILEGES ON keystone.* TO 'keystone'@'localhost';
GRANT ALL PRIVILEGES ON keystone.* TO 'keystone'@'127.0.0.1';
GRANT ALL PRIVILEGES ON keystone.* TO 'keystone'@'%';
FLUSH PRIVILEGES;
EXIT;
```

```bash
mysql -uroot -NBe "SELECT SCHEMA_NAME FROM information_schema.SCHEMATA WHERE SCHEMA_NAME='keystone';"
mysql -uroot -NBe "SELECT Host FROM mysql.user WHERE User='keystone' ORDER BY Host;"
```

预期 Host 集合精确为 `%`、`127.0.0.1`、`localhost`，其全局权限只有 USAGE，数据库权限只指向 `keystone.*`。

## 6.3 手工配置与同步数据库

### 6.3.1 备份软件包默认配置

```bash
umask 077
stamp=$(date -u +%Y%m%dT%H%M%SZ)
backup=/root/openstack-lab-backups/keystone-$stamp
install -d -m 0700 "$backup"
cp -a /etc/keystone/keystone.conf "$backup"/
```

### 6.3.2 使用vi编辑keystone.conf

```bash
vi /etc/keystone/keystone.conf
```

```ini
[database]
connection = mysql+pymysql://keystone:<URL_ENCODED_DB_PASSWORD>@127.0.0.1/keystone

[token]
provider = fernet
```

如口令含 `@`、`:`、`/`、`%` 等 URL 保留字符，必须先完成 URL 编码。配置文件中使用 `<URL_ENCODED_DB_PASSWORD>` 只是教材占位符。

```bash
chown root:keystone /etc/keystone/keystone.conf
chmod 0640 /etc/keystone/keystone.conf
```

### 6.3.3 手工执行keystone-manage db_sync

```bash
su -s /bin/sh -c 'keystone-manage db_sync' keystone
```

### 6.3.4 核对数据表与迁移状态

```bash
mysql -uroot -NBe "SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='keystone';"
mysql -uroot -NBe 'SELECT version_num FROM keystone.alembic_version ORDER BY version_num;'
```

实测应有 49 张表，`alembic_version` 中为两个迁移头。表数不正常时先查配置和日志，不应通过删库来掩盖失败。

## 6.4 Fernet与Credential密钥

### 6.4.1 初始化Fernet密钥库

```bash
keystone-manage fernet_setup --keystone-user keystone --keystone-group keystone
```

### 6.4.2 初始化Credential密钥库

```bash
keystone-manage credential_setup --keystone-user keystone --keystone-group keystone
```

### 6.4.3 文件权限和密钥保护

```bash
stat -c '%U:%G %a %n' /etc/keystone/fernet-keys /etc/keystone/credential-keys
find /etc/keystone/fernet-keys /etc/keystone/credential-keys -maxdepth 1 -type f \
  -printf '%u:%g %m %p\n'
```

实测目录为 `keystone:keystone 0700`，密钥文件为 `0600`。不运行 `cat`、不记录摘要，不因重跑实训而静默轮换已有的完整密钥集。

## 6.5 初始化身份服务

### 6.5.1 手工执行Keystone bootstrap

```bash
read -s -p 'Keystone admin password: ' ADMIN_PASS; echo
keystone-manage bootstrap \
  --bootstrap-password "$ADMIN_PASS" \
  --bootstrap-username admin \
  --bootstrap-project-name admin \
  --bootstrap-role-name admin \
  --bootstrap-service-name keystone \
  --bootstrap-admin-url http://controller:5000/v3/ \
  --bootstrap-internal-url http://controller:5000/v3/ \
  --bootstrap-public-url http://controller:5000/v3/ \
  --bootstrap-region-id RegionOne
unset ADMIN_PASS
```

bootstrap 一次建立 Default 域、admin 项目/用户/角色、identity 服务和三端点。如重跑时对象已存在，应先查询数据库和 CLI 证据；部分存在不得当作完整成功。

### 6.5.2 核对identity服务和三类端点

在 Apache 就绪后执行 `openstack service list` 和 `openstack endpoint list --service identity`。三个端点必须是 RegionOne、public/internal/admin、URL 精确为 `http://controller:5000/v3/`。

### 6.5.3 配置Apache WSGI并启动服务

```bash
vi /etc/httpd/conf.d/00-servername.conf
```

```text
ServerName controller
```

```bash
ln -s /usr/share/keystone/wsgi-keystone.conf /etc/httpd/conf.d/wsgi-keystone.conf
httpd -t
systemctl enable --now httpd
systemctl is-active httpd
systemctl is-enabled httpd
ss -lnt | grep ':5000'
curl --noproxy '*' -sS -o /dev/null -w '%{http_code}\n' http://controller:5000/v3/
```

预期 `/v3/` 返回 200，老版 35357 端口不应监听。

## 6.6 创建项目、用户、角色与授权

### 6.6.1 创建service项目

先手工编写管理员环境文件：

```bash
vi /root/admin-openrc
```

```bash
export OS_PROJECT_DOMAIN_NAME=Default
export OS_USER_DOMAIN_NAME=Default
export OS_PROJECT_NAME=admin
export OS_USERNAME=admin
export OS_AUTH_URL=http://controller:5000/v3
export OS_IDENTITY_API_VERSION=3
export OS_IMAGE_API_VERSION=2
export OS_REGION_NAME=RegionOne
read -s -p 'OS_PASSWORD: ' OS_PASSWORD; echo
export OS_PASSWORD
```

```bash
chmod 0600 /root/admin-openrc
source /root/admin-openrc
openstack token issue
openstack project create --domain default --description 'Service Project' service
openstack project show service
```

不将真实管理员口令写入 OpenRC。课堂上可在 source 后交互输入，使用完立即 `unset OS_PASSWORD`。

### 6.6.2 创建演示项目和用户

```bash
source /root/admin-openrc
openstack project create --domain default --description 'Demo Project' demo
openstack user create --domain default --password-prompt demo
openstack role show member
```

### 6.6.3 创建角色并完成项目授权

```bash
openstack role add --project demo --user demo member
openstack role assignment list --project demo --user demo --names
unset OS_PASSWORD
```

### 6.7.3 Keystone轻量验收与故障定位

轻量验收为：`httpd active/enabled`；5000 `/v3/` 返回 200；令牌签发成功；identity 服务唯一，三端点精确；service 项目唯一。常见故障定位：

- 5000 无监听：`httpd -t`、`systemctl status httpd`、`journalctl -u httpd`。
- `Unauthorized`：检查域、项目、用户、口令和 `OS_AUTH_URL`，不在命令中打印口令。
- 同步失败：检查 URL 编码、MariaDB 三 Host 授权和 `/var/log/keystone/`。
- 令牌失败：检查 Fernet 目录的完整性和权限，不随意重建密钥。

## 6.8 素养拓展与本章总结

### 6.8.1 素养拓展：最小权限、数据安全与工程职业道德

权限不是“能用就行”的技术细节，而是工程人员对用户和数据承担的责任。本章将数据库授权限定在 `keystone.*`，将角色绑定在具体项目，不在文档中留存口令和密钥。这些不是附加手续，而是职业道德在配置行中的具体体现。请思考：为了省事给所有数据库用户授予全局权限，会把哪些组织风险转嫁给业务用户？

### 6.8.2 本章小结、复习题与拓展任务

Keystone 已建立云平台的信任根：数据库保存身份与授权元数据，Fernet 密钥支持令牌，Apache WSGI 暴露 v3 API，服务目录为后续组件提供可发现地址。

1. 区分域、项目、用户和角色。
2. public、internal、admin 端点为何应当全部保留？
3. 为什么 Fernet 密钥不能在重跑实训时静默重建？
4. 设计一张“用户—项目—角色”绑定检查表。
