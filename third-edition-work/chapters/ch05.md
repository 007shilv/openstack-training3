# 第5章 基础环境、离线源与公共服务

## 学习目标

完成本章学习后，应能说明 OpenStack 控制面对主机解析、时间、数据库、消息队列和缓存的依赖；在 openEuler 24.03 LTS SP3 上固定双节点地址，保持 Provider 网卡无 IP；只使用 `openstack-local` 离线源安装 MariaDB、RabbitMQ、Memcached 和 OpenStack 客户端；逐条手工编辑配置、启动服务并完成轻量验收。

> 本篇手工实训约定：学生在命令行逐条输入命令，用 `vi` 逐个编辑配置文件。`openstack-ts` 只是版本、参数和顺序的校核依据，不是第二篇的安装入口。

## 5.1 构建顺序与实验边界

### 5.1.1 组件依赖和安装先后关系

OpenStack 将一个云平台拆成多个协作服务。Keystone 、Glance、Placement、Nova、Neutron 和 Cinder 都需要持久化数据库，并通过 RabbitMQ 交换异步消息；Keystone 令牌验证会使用 Memcached。因此正确顺序是：主机与软件源 → 时间同步 → MariaDB → RabbitMQ → Memcached → OpenStack CLI → Keystone 与后续组件。如图5.1所示，前一阶段没有验收就不得开始后一阶段。

**图5.1　OpenStack Antelope 双节点手工构建顺序（建议自绘流程图）**

### 5.1.2 教学环境与生产环境的边界

本书使用一个 controller 和一个 compute，实验 OpenStack 2023.1 Antelope，操作系统为 openEuler 24.03 LTS SP3。Antelope 组件包来自已复核的 SP2 仓库闭包，并经实机验证可在 SP3 上运行。实验为了突出组件原理，使用 HTTP、SELinux Permissive 和关闭防火墙等教学简化。生产环境必须启用 TLS、SELinux Enforcing、最小化防火墙规则、高可用数据库与消息队列，并将不同服务口令分离保管。

### 5.1.3 手工部署规则和轻量验收规则

每个服务都采用“前置检查—安装包—手工建库/注册身份—`vi` 配置—手工同步数据库—启用并启动—验证”模板。普通组件的轻量验收只需证明：相关服务 `active/enabled`，API 有正常响应，一条代表性 CLI 或最小功能测试成功。涉及磁盘初始化、覆盖配置或删除资源时，则保留“目标精确确认、失败即停、按精确 ID 清理”门禁。

## 5.2 主机名、地址与解析

### 5.2.1 设置 controller 与 compute 主机名

在 controller 和 compute 分别执行：

```bash
# controller
hostnamectl set-hostname controller

# compute
hostnamectl set-hostname compute
```

### 5.2.2 固定 ens33 管理地址

表5-1给出实验地址。在两节点通过 `vi` 编辑 ens33 的 NetworkManager 连接文件，设为手工 IPv4；具体网关和 DNS 以实验室网段为准。

| 表5-1　双节点地址规划 | 主机名 | ens33 管理地址 | ens34 |
| --- | --- | --- | --- |
| 控制节点 | controller | 192.168.234.151/24 | 无 IP |
| 计算/存储节点 | compute | 192.168.234.150/24 | 无 IP |

```bash
nmcli connection show
vi /etc/NetworkManager/system-connections/ens33.nmconnection
nmcli connection reload
nmcli connection up ens33
ip -4 -o address show dev ens33
```

### 5.2.3 保持 ens34 无 IP 地址

ens34 是后续 Neutron `provider:ens34` 的底层网卡，不承载主机管理地址。两节点均执行：

```bash
ip -4 -o address show dev ens34
ip -6 -o address show dev ens34 scope global
```

两条命令均应无输出。不要为了“测试网卡”临时给 ens34 加地址。

### 5.2.4 配置 hosts 与双向连通

两节点手工编辑 `/etc/hosts`：

```bash
vi /etc/hosts
```

```text
192.168.234.151 controller
192.168.234.150 compute
```

```bash
getent ahostsv4 controller
getent ahostsv4 compute
ping -c 2 controller
ping -c 2 compute
```

## 5.3 OpenStack 离线软件源

### 5.3.1 本地源目录和完整性检查

教师将已校验的离线 RPM 展开在 controller。不应从未审核的网页临时补包。查看元数据、包数和已发布的 SHA-256 清单，不修改原始压缩包。

```bash
find /var/ftp/openstack_repo -maxdepth 2 -type f -name repomd.xml -o -name '*.rpm' | head
sha256sum -c SHA256SUMS.txt
```

### 5.3.2 controller 文件源与 compute 访问路径

controller 使用 `file://`，compute 使用 controller 提供的只读 FTP 路径。分别用 `vi /etc/yum.repos.d/openstack-local.repo` 建立如下配置（实际目录以教师发放说明为准）：

```ini
# controller
[openstack-local]
name=Validated local OpenStack repository
baseurl=file:///var/ftp/openstack_repo
enabled=1
gpgcheck=0
```

```ini
# compute
[openstack-local]
name=Validated controller OpenStack repository
baseurl=ftp://192.168.234.151/openstack_repo
enabled=1
gpgcheck=0
```

### 5.3.3 隔离外部源并验证软件包来源

```bash
dnf clean all
dnf -q makecache --disablerepo='*' --enablerepo='openstack-local'
dnf -q repolist --disablerepo='*' --enablerepo='openstack-local'
dnf repoquery --disablerepo='*' --enablerepo='openstack-local' python3-openstackclient
```

后续所有 DNF 命令都必须显式带上 `--disablerepo='*' --enablerepo='openstack-local'`。如事务计划出现删除、替换或降级，停止而不是添加 `--allowerasing`。

### 5.3.4 SP3 系统与 SP2 Antelope 包的兼容组合

```bash
dnf -y --disablerepo='*' --enablerepo='openstack-local' install openstack-release-antelope
rpm -q openstack-release-antelope
vi /etc/yum.repos.d/openstack-antelope.repo
```

将 release 包生成的 Antelope 路径中 `openEuler-24.03-LTS-SP3` 手工改为经复核的 `openEuler-24.03-LTS-SP2`。这表示“SP3 操作系统+SP2 Antelope 组件包”，不是将操作系统降级。实验已验证 release 包为 `1.0.6-6.oe2403sp3`。

## 5.4 时间同步与基础安全设置

### 5.4.1 配置 chrony 服务

两节点手工编辑 `/etc/chrony.conf`，然后执行：

```bash
dnf -y --disablerepo='*' --enablerepo='openstack-local' install chrony
systemctl enable --now chronyd
chronyc -a makestep
chronyc tracking
chronyc sources
timedatectl show -p NTPSynchronized --value
```

Leap status 应为 Normal，`NTPSynchronized` 应为 `yes`。时钟偏差会使令牌过期、消息时序混乱并干扰日志定位。

### 5.4.2 教学简化设置及生产安全说明

```bash
vi /etc/selinux/config
setenforce 0
systemctl disable --now firewalld
getenforce
systemctl is-active firewalld
systemctl is-enabled firewalld
```

将 `SELINUX=permissive`，预期输出为 Permissive、inactive、disabled。这一设置只适用于隔离教学网，不可作为生产问题的通用“解决方法”。

## 5.5 MariaDB 数据库服务

### 5.5.1 安装并配置 MariaDB

```bash
dnf -y --setopt=install_weak_deps=False --disablerepo='*' --enablerepo='openstack-local' install \
  mariadb-config mariadb mariadb-server python3-PyMySQL
vi /etc/my.cnf.d/openstack.cnf
```

```ini
[mysqld]
bind-address = 0.0.0.0
default-storage-engine = innodb
innodb_file_per_table = on
max_connections = 4096
collation-server = utf8_general_ci
character-set-server = utf8
```

### 5.5.2 字符集、连接数与监听参数

UTF-8 保证项目名、镜像属性等元数据的一致性；`innodb_file_per_table` 便于表空间管理；4096 是两节点教学环境的连接上限。监听 `0.0.0.0` 是为了让 compute 上的 Cinder volume 连接 controller，但生产环境应用防火墙将 3306 限制在专用管理网。

### 5.5.3 启动、开机启动与验证

```bash
systemctl enable --now mariadb
systemctl is-active mariadb
systemctl is-enabled mariadb
mysql -uroot -e 'SELECT 1;'
mysql -uroot -NBe 'SELECT @@bind_address,@@default_storage_engine,@@innodb_file_per_table,@@max_connections,@@collation_server,@@character_set_server;'
ss -lnt | grep ':3306'
```

## 5.6 RabbitMQ 消息队列

### 5.6.1 安装并启动 RabbitMQ

```bash
dnf -y --setopt=install_weak_deps=False --disablerepo='*' --enablerepo='openstack-local' install rabbitmq-server
systemctl enable --now rabbitmq-server
```

### 5.6.2 手工创建 openstack 用户和权限

用 `read -s` 避免口令出现在屏幕和历史中：

```bash
read -s -p 'RabbitMQ password: ' RABBIT_PASS; echo
rabbitmqctl add_user openstack "$RABBIT_PASS"
rabbitmqctl set_permissions openstack '.*' '.*' '.*'
rabbitmqctl authenticate_user openstack "$RABBIT_PASS"
unset RABBIT_PASS
```

如用户已存在，先执行 `rabbitmqctl list_users`，经确认后使用 `change_password`，不得因“已存在”而忽略完整性检查。

### 5.6.3 认证、监听与故障检查

```bash
systemctl is-active rabbitmq-server
systemctl is-enabled rabbitmq-server
rabbitmqctl list_users
rabbitmqctl list_user_permissions openstack
ss -lnt | grep ':5672'
journalctl -u rabbitmq-server -n 30 --no-pager
```

## 5.7 Memcached 与 OpenStack 客户端

### 5.7.1 安装并手工配置 Memcached

```bash
dnf -y --setopt=install_weak_deps=False --disablerepo='*' --enablerepo='openstack-local' install \
  memcached python3-memcached python3-openstackclient
vi /etc/sysconfig/memcached
```

```text
PORT="11211"
USER="memcached"
MAXCONN="1024"
CACHESIZE="64"
OPTIONS="-l 127.0.0.1,::1,192.168.234.151"
```

### 5.7.2 启动服务并验证监听

```bash
systemctl enable --now memcached
systemctl is-active memcached
systemctl is-enabled memcached
ss -lnt | grep ':11211'
```

监听集应精确包含 `127.0.0.1`、`::1` 和 `192.168.234.151`，不应包含无限制的外部通配地址。

### 5.7.3 安装和检查 OpenStack 客户端

```bash
openstack --version
```

实验验证版本为 `openstack 6.2.0`。此时尚未配置 Keystone，因此不应执行需要令牌的命令。

## 5.8 综合核验与故障处理

### 5.8.1 公共服务状态和端口核验

```bash
for s in chronyd mariadb rabbitmq-server memcached; do
  systemctl is-active "$s"
  systemctl is-enabled "$s"
done
ss -lnt | grep -E ':(3306|5672|11211)'
dnf -q repolist --disablerepo='*' --enablerepo='openstack-local'
```

### 5.8.2 软件源、时间和基础服务故障

- `Cannot download repomd.xml`：先检查 controller 目录、FTP 可达性和 `baseurl`，不切换到未审核外部源。
- 令牌时间错误：本章尚无令牌，但应提前用 `chronyc tracking` 处理时间异常。
- MariaDB 不监听：检查 `openstack.cnf` 语法、`journalctl -u mariadb`和 3306 监听，不重复覆盖数据目录。
- RabbitMQ 认证失败：查用户、vhost 权限和口令是否一致，不在日志中显示口令。
