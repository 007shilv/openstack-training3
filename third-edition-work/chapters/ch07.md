# 第7章 Glance镜像与Placement资源服务

## 学习目标

掌握 Glance 镜像生命周期和 Placement 资源跟踪模型；理解 Keystone→Glance→Placement→Nova 的构建顺序；对两项服务分别手工建库与三 Host 授权、创建用户/角色/服务/三端点、用 `vi` 配置、手工同步数据库并启动 API；使用合成镜像和认证 REST 完成轻量验收。

## 7.1 两项服务的定位与构建顺序

### 7.1.1 镜像数据流与资源跟踪流程

Glance API 保存镜像元数据，并把镜像字节写入后端。本实验使用 `/var/lib/glance/images/` 文件后端。Placement 不创建虚拟机，而是记录资源提供者、库存和分配，供 Nova Scheduler 做决策。图7.1应同时表达“镜像数据流”和“计算资源上报流”。

### 7.1.2 Keystone、Glance、Placement与Nova的依赖关系

Glance 和 Placement 都需要 Keystone 服务用户与端点。Nova 需要从 Glance 取镜像、向 Placement 查资源，因此两者必须在 Nova 之前完成。

## 7.2 手工部署Glance的数据库和身份对象

### 7.2.1 创建glance数据库、用户与授权

```bash
dnf -y --disablerepo='*' --enablerepo='openstack-local' --setopt=install_weak_deps=False install openstack-glance
mysql -uroot
```

```sql
CREATE DATABASE glance;
CREATE USER 'glance'@'localhost' IDENTIFIED BY '<DB_PASSWORD>';
CREATE USER 'glance'@'127.0.0.1' IDENTIFIED BY '<DB_PASSWORD>';
CREATE USER 'glance'@'%' IDENTIFIED BY '<DB_PASSWORD>';
GRANT ALL PRIVILEGES ON glance.* TO 'glance'@'localhost';
GRANT ALL PRIVILEGES ON glance.* TO 'glance'@'127.0.0.1';
GRANT ALL PRIVILEGES ON glance.* TO 'glance'@'%';
FLUSH PRIVILEGES;
EXIT;
```

### 7.2.2 创建glance服务用户和角色授权

```bash
source /root/admin-openrc

openstack user show glance
openstack role add --project service --user glance admin
openstack role assignment list --project service --user glance --role admin
```

### 7.2.3 创建image服务和三类端点

## 7.3 手工配置并启动Glance

### 7.3.1 安装软件包并备份默认配置

```bash
umask 077; backup=/root/openstack-lab-backups/glance-$(date -u +%Y%m%dT%H%M%SZ)
install -d -m 0700 "$backup"
cp -a /etc/glance/glance-api.conf "$backup"/
vi /etc/glance/glance-api.conf
```

### 7.3.2 使用vi编辑glance-api.conf

```ini
[DEFAULT]
enabled_backends = file:file

[database]
connection = mysql+pymysql://glance:<URL_ENCODED_DB_PASSWORD>@127.0.0.1/glance

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = glance
password = <SERVICE_PASSWORD>

[paste_deploy]
flavor = keystone

[glance_store]
default_backend = file

[file]
filesystem_store_datadir = /var/lib/glance/images/
```

```bash
chown root:glance /etc/glance/glance-api.conf; chmod 0640 /etc/glance/glance-api.conf
```

### 7.3.3 手工同步数据库

```bash
su -s /bin/sh -c 'glance-manage db_sync' glance
mysql -uroot -NBe "SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='glance';"
```

实测为14张表，必需表包括 `images`、`image_locations`、`image_members`、`image_properties`、`image_tags`。

### 7.3.4 启用、启动与检查Glance API

```bash
systemctl enable --now openstack-glance-api
systemctl is-active openstack-glance-api; systemctl is-enabled openstack-glance-api
ss -lnt | grep ':9292'
curl --noproxy '*' -sS -o /dev/null -w '%{http_code}\n' http://controller:9292/
```

## 7.4 Glance镜像生命周期验证

### 7.4.1 创建并上传最小测试镜像

为不依赖互联网，生成一个非启动合成 raw 文件验证数据通路：

```bash
printf 'OPENSTACK-GLANCE-VALIDATION\n' >/root/glance-test.raw
source /root/admin-openrc
image_id=$(openstack image create task7-glance-image --private --disk-format raw \
  --container-format bare --file /root/glance-test.raw -f value -c id)
openstack image show "$image_id"
```

### 7.4.2 查询、下载和按精确ID删除镜像

```bash
openstack image save --file /root/glance-test.download "$image_id"
sha256sum /root/glance-test.raw /root/glance-test.download
openstack image delete "$image_id"
openstack image list
rm -f /root/glance-test.raw /root/glance-test.download
unset OS_PASSWORD
```

### 7.4.3 镜像服务常见故障

9292无响应先查 `journalctl -u openstack-glance-api`；401检查 Keystone 端点与 `[keystone_authtoken]`；镜像一直 `queued`检查后端目录属主、空间和 `enabled_backends`。清理必须使用创建时记录的精确 ID。


### 7.6.4 配置Apache并启动Placement API

手工编辑 `/etc/httpd/conf.d/00-placement-api.conf`，只保留 8778 VirtualHost 根 WSGI 映射，删除会把 Placement 暴露在 80/5000 的全局 `/placement-api` Alias/Location。

```bash

systemctl is-active httpd; systemctl is-enabled httpd
ss -lnt | grep ':8778'
```

## 7.7 Placement API验证与资源理解

### 7.7.1 版本发现和认证查询

```bash
source /root/admin-openrc
token=$(openstack token issue -f value -c id)
curl --noproxy '*' -sS -H "X-Auth-Token: $token" \
  -H 'OpenStack-API-Version: placement 1.39' \
  http://controller:8778/resource_providers
unset token OS_PASSWORD
```

此时预期 `resource_providers` 是空列表：表示认证查询成功但 Nova compute 尚未上报，不是 API 失败。本地源未含 `osc-placement` CLI 插件，因此不以 `openstack resource provider list` 为验收门禁。

### 7.7.2 Resource Provider、Inventory与Allocation

Resource Provider 代表可提供资源的对象；Inventory 记录 VCPU、MEMORY_MB、DISK_GB 等总量、保留量和超分比；Allocation 表示消费者已占用的数量。Nova 安装后由 `nova-compute` 自动注册 provider 和 inventory，不手工造数据。

### 7.7.3 Placement常见故障

8778返回404时检查 WSGI VirtualHost；401检查令牌与 `WSGIPassAuthorization On`；升级检查失败时 API 不应抢先开放；数据表不完整时先比较迁移头，不删库重来。
