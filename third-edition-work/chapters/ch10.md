# 第10章 Cinder与Swift存储服务

## 学习目标

区分块存储与对象存储；在写盘前用失效即停门禁精确识别 `/dev/sda`、`/dev/sdb`、`/dev/sdc`；手工部署 Cinder 控制面和 LVM/iSCSI 后端；手工部署 Swift Proxy、单副本 rings 与 compute 存储服务；完成卷与对象的最小生命周期验收。

## 10.1 云存储架构与磁盘安全

### 10.1.1 块存储、对象存储与文件存储

Cinder 以“卷”向实例提供块设备，实例内决定文件系统；Swift 以容器/对象/API 组织数据，不提供通用 POSIX 挂载；文件存储向多客户端提供共享目录。图10.1建议绘制三种存储访问语义对比。

### 10.1.2 /dev/sda、/dev/sdb与/dev/sdc边界

| 表10-1　compute磁盘边界 | 容量 | 用途 | 允许初始化 |
| --- | ---: | --- | --- |
| /dev/sda | 200 GiB | openEuler系统盘 | 否 |
| /dev/sdb | 50 GiB | Cinder cinder-volumes PV/VG | 仅Cinder阶段 |
| /dev/sdc | 50 GiB | Swift XFS，挂载/srv/node/sdc | 仅Swift阶段 |

### 10.1.3 写入前的分区、签名、挂载、LVM和根盘检查

```bash
target=/dev/sdb
[[ $target == /dev/sdb && -b $target ]]
[[ $(lsblk -dnro TYPE "$target") == disk ]]
[[ $(blockdev --getsize64 "$target") == 53687091200 ]]
root=$(readlink -f "$(findmnt -nro SOURCE /)")
! lsblk -s -nrpo NAME "$root" | grep -Fxq "$target"
[[ $(lsblk -nrpo NAME "$target" | sed '/^$/d' | wc -l) -eq 1 ]]
[[ -z $(findmnt -nro TARGET --source "$target") ]]
[[ -z $(wipefs --no-act --noheadings --output TYPE "$target") ]]
```

每个探针都必须成功返回明确结果；探针报错不得解释为“空盘”。

### 10.1.4 教学盘可重置与生产数据保护

用户已明确两块 50 GiB 为无数据教学盘，但教材仍保留目标、容量、根盘祖先、签名、挂载和 PV 检查。生产环境还应有备份、变更单、双人复核和回退预案。

### 10.3.2 手工创建PV与cinder-volumes VG


## 10.4 Cinder卷生命周期验证

### 10.4.1 创建、查询和删除测试卷

```bash
source /root/admin-openrc
volume_id=$(openstack volume create --size 1 --type lvm task10-volume -f value -c id)
openstack volume show "$volume_id"
openstack volume delete "$volume_id"
openstack volume list --name task10-volume
```

### 10.4.2 LVM Thin Pool与任务卷边界

Cinder 在 `cinder-volumes` 中创建 thin pool 与卷 LV。清理只通过 Cinder API 按卷 ID，不手工删 LV，否则会破坏数据库与后端一致性。

### 10.4.3 Cinder常见故障

`down` 检查 RabbitMQ/时间/口令；卷长期 `creating` 检查 VG、backend name、scheduler 和 volume 日志；8776故障检查 API 与三端点；不格式化 `/dev/sdb` 试错。

## 10.5 Swift架构与单副本教学设计

### 10.5.1 Proxy、Account、Container与Object服务

Proxy 认证并路由 API；Account 维护账户与容器索引；Container 维护对象列表；Object 保存数据。

### 10.5.2 Ring与数据放置

Ring 根据分区、区域/可用区、设备和权重映射对象位置。本实验 account/container/object ring 都只含 `192.168.234.150/sdc`。

### 10.5.3 单设备单副本的限制

副本数为1仅用于两节点教学，无任何生产级冗余；设备、节点或站点失效都可造成数据不可用。

## 10.6 Swift控制节点手工部署

### 10.6.1 创建swift用户、角色授权、object-store服务和三类端点

```bash
source /root/admin-openrc
openstack user create --domain Default --password-prompt swift
openstack role add --project service --user swift admin
openstack service create --name swift --description 'OpenStack Object Storage' object-store
for i in public internal admin; do openstack endpoint create --region RegionOne object-store "$i" 'http://controller:8080/v1/AUTH_%(project_id)s'; done
```

### 10.6.2 使用vi配置swift.conf与proxy-server.conf

```bash
dnf -y --disablerepo='*' --enablerepo=openstack-local install openstack-swift-proxy python3-swiftclient
vi /etc/swift/swift.conf
```

```ini
[swift-hash]
swift_hash_path_prefix = <RUNTIME_RANDOM_PREFIX>
swift_hash_path_suffix = <RUNTIME_RANDOM_SUFFIX>
[storage-policy:0]
name = Policy-0
default = yes
```

`proxy-server.conf` 使用 `catch_errors gatekeeper healthcheck proxy-logging cache authtoken keystoneauth proxy-logging proxy-server` pipeline；authtoken 连 controller:5000、Memcached、service/swift，口令使用 `<SERVICE_PASSWORD>`；proxy 开启 `account_autocreate=true`。

### 10.6.3 手工创建Account、Container与Object Ring

```bash
cd /etc/swift
swift-ring-builder account.builder create 10 1 1
swift-ring-builder container.builder create 10 1 1
swift-ring-builder object.builder create 10 1 1
swift-ring-builder account.builder add --region 1 --zone 1 --ip 192.168.234.150 --port 6202 --device sdc --weight 100
swift-ring-builder container.builder add --region 1 --zone 1 --ip 192.168.234.150 --port 6201 --device sdc --weight 100
swift-ring-builder object.builder add --region 1 --zone 1 --ip 192.168.234.150 --port 6200 --device sdc --weight 100
swift-ring-builder account.builder rebalance
swift-ring-builder container.builder rebalance
swift-ring-builder object.builder rebalance
```

### 10.6.4 安全分发配置和Ring文件

在已人工核对主机指纹的前提下，逐个 `scp -o StrictHostKeyChecking=yes` 分发 `swift.conf` 和三个 `.ring.gz`，然后用 `cmp` 比较字节一致；不打印 hash salt。

## 10.7 Swift存储节点手工部署

### 10.7.1 再次确认/dev/sdc为50 GiB教学盘

目标必须精确为 `/dev/sdc`，不在根盘祖先链，无分区/挂载/签名/PV；同时确认 `/dev/sdb` 唯一属于 `cinder-volumes`。

### 10.7.2 手工格式化XFS并按UUID挂载

```bash
read -r -p '确认/dev/sdc为空白50GiB教学盘，输入YES：' confirm; [[ $confirm == YES ]]
mkfs.xfs -f -L swift-data /dev/sdc
uuid=$(blkid -o value -s UUID /dev/sdc)
install -d -m 0755 /srv/node/sdc
vi /etc/fstab
# UUID=<上步UUID> /srv/node/sdc xfs defaults,noatime,nodiratime 0 0
mount /srv/node/sdc
```

### 10.7.3 使用vi配置rsync和三个存储服务

`/etc/rsyncd.conf` 以 swift 运行，绑定 `.150`，建立 account/container/object 三模块，path 均 `/srv/node/`。`account-server.conf`、`container-server.conf`、`object-server.conf` 分别绑定 6202、6201、6200，`devices=/srv/node`、`mount_check=true`，包含 healthcheck/recon 和各自 server pipeline。所有文件均用 `vi` 完整输入，最后 `chown -R swift:swift /etc/swift /srv/node /var/cache/swift`。

### 10.7.4 依次启用、启动和验证服务

```bash
systemctl enable --now rsyncd
systemctl enable --now openstack-swift-account
systemctl enable --now openstack-swift-container
systemctl enable --now openstack-swift-object
for s in rsyncd openstack-swift-account openstack-swift-container openstack-swift-object; do systemctl is-active "$s"; systemctl is-enabled "$s"; done
```

controller 启动 `systemctl enable --now openstack-swift-proxy`，检查 8080 `/healthcheck`。

## 10.9 素养拓展与本章总结

### 10.9.1 素养拓展：网络存储安全、数据责任与底线意识

一条错误的 `mkfs` 可以让多年数据在秒级内丢失。对数据的敬畏必须落实为可执行的底线：目标精确、根链排除、多探针一致、人工确认、最小写入和可审计记录。教学盘可重置不等于工程人员可以养成忽略数据边界的习惯。
