# 第九章 Nova的安装及其配置

本章导读：Nova是OpenStack中负责计算资源和虚拟机实例生命周期的核心服务。它接收用户的实例请求，结合Placement提供的资源信息选择计算节点，再由计算节点上的虚拟化程序创建实例。Nova依赖Keystone、Glance、Placement、MariaDB和RabbitMQ，因此必须在前述服务完成后部署，并严格遵循控制节点先于计算节点的顺序。

Nova并不直接提供物理处理器、内存和磁盘，它把计算节点上的虚拟化能力组织为统一服务。控制节点保存实例状态、执行调度和协调任务，计算节点负责真正创建和运行虚拟机。理解两类节点的职责，有助于把控制面故障与计算资源故障区分开。

图9.1表示Nova在双节点环境中的组件分布。图中蓝色区域为控制节点进程，绿色区域为计算节点进程，底部的Placement、Glance、Keystone和RabbitMQ是Nova运行时依赖的公共服务。

{{FIGURE:图9.1}}

图9.1中，nova-api接收请求，nova-scheduler选择计算节点，nova-conductor协调数据库访问，nova-novncproxy提供实例控制台入口；compute节点上的nova-compute调用libvirt和QEMU完成实例创建。组件之间通过RabbitMQ传递任务，通过数据库保存状态，并分别访问身份、镜像和资源服务。

## 9.1 Nova功能与组件

一．Nova控制平面

1．API与任务协调

nova-api是计算服务的请求入口，负责解析创建、删除、调整和查询实例等操作。请求通过Keystone认证后进入Nova内部流程，API进程不会直接在计算节点上执行虚拟化命令，而是把任务交给后续服务。

nova-conductor位于API、调度器和计算节点之间，承担数据库访问和部分任务协调。计算节点不直接连接Nova数据库，可以减少数据库凭据向计算节点扩散，并把数据访问集中在控制平面。

2．调度与控制台服务

nova-scheduler根据实例规格、可用资源、资源特征和调度策略选择目标计算节点。Placement提供候选资源事实，调度器再结合过滤与权重形成最终选择。调度不是简单寻找“空闲最多”的主机，而是判断请求是否满足计算、内存、磁盘和特征等条件。

VNC（Virtual Network Computing，虚拟网络计算）用于远程显示实例控制台。nova-novncproxy把浏览器的noVNC连接转发到计算节点上的实例控制台，使管理员在实例网络尚未配置时仍可观察启动过程。

二．Nova计算平面

1．nova-compute与libvirt

nova-compute运行在compute节点上，接收控制面下发的实例任务，并持续上报可用资源。它通过libvirt访问QEMU或KVM，完成虚拟机定义、磁盘连接、网络接口创建和电源状态管理。

本书实验虚拟机没有向内部虚拟机暴露硬件虚拟化扩展，因此在nova.conf中使用qemu模式。生产服务器具有硬件虚拟化能力时通常使用KVM，以获得更接近原生的处理器性能。两种模式的Nova调用关系相同，差异主要位于虚拟化执行层。

2．计算节点身份与资源上报

每个计算节点使用稳定的compute_id标识自身。该标识与主机映射、计算服务记录及Placement资源提供者相联系，不能在服务运行后随意更换。重装计算节点前需要保留或明确重建其身份关系。

nova-compute启动后把处理器、内存和本地磁盘等资源登记到Placement。调度器取得资源候选后，Nova为实例建立分配记录，从而避免不同请求同时占用同一份资源。

## 9.2 Cell v2与实例创建过程

一．Cell v2架构

1．API数据库与主数据库

Cell v2（Cell version 2，第二代单元架构）把Nova控制面划分为API层和一个或多个资源单元。nova_api数据库保存面向全局请求的数据，nova数据库保存cell1中的实例和计算资源状态，nova_cell0用于记录没有成功调度到计算节点的实例。

三类数据库分别承担不同职责，不能合并为同一个数据库名称。安装时先同步nova_api，再注册cell0和创建cell1，最后同步主数据库。顺序颠倒会造成映射缺失或实例记录无法进入正确单元。

2．cell0、cell1与主机映射

cell0没有计算节点，只保存调度失败的实例记录。cell1承载本书双节点环境中的compute节点。Nova还通过主机映射把计算服务归入cell1，使API能够从全局请求找到具体资源单元。

Cell架构为大规模平台提供故障隔离和横向扩展能力。一个小型环境只使用cell1，也仍要保留完整的API数据库、cell0和cell1关系，因为这些对象是Nova Antelope的基本运行结构。

二．实例创建调用顺序

1．从请求到调度

管理员或Horizon向nova-api提交实例名称、镜像、实例规格和网络等参数。nova-api完成身份与参数处理后，调度器把实例规格转换为资源请求，再向Placement取得满足条件的资源提供者候选。

2．从资源分配到虚拟机

调度器确定compute节点后，Nova建立资源分配，并通过RabbitMQ把创建任务交给nova-compute。nova-compute从Glance取得镜像，通过Neutron连接网络，通过libvirt创建虚拟机，最后把实例状态写回控制面。

## 9.3 实训项目6 Nova的手工安装与配置

一．实训前提环境

controller和compute已经完成openEuler 24.03 LTS SP3基础环境配置，教材配套本地软件仓处于启用状态。Keystone、Glance和Placement已经按照前述章节完成，controller上的MariaDB、RabbitMQ、Memcached和Apache处于运行状态。

二．实训涉及节点

Nova控制服务安装在controller 192.168.234.151，nova-compute、QEMU和libvirt安装在compute 192.168.234.150。命令必须在对应节点终端逐条输入，控制节点完成并启动服务后再配置计算节点。

三．实训目标

1．完成nova_api、nova和nova_cell0数据库及三个来源账户的手工创建。

2．完成nova服务用户、角色授权、compute服务和三个端点创建。

3．完成Nova控制节点软件安装、nova.conf配置、数据库同步和Cell v2初始化。

4．完成Nova控制服务、libvirt和nova-compute的顺序启动。

5．完成计算节点配置和主机发现，使compute加入cell1。

四．实训步骤及其详解

步骤一：创建Nova数据库和账户

在controller进入MariaDB，创建三个数据库。实验环境统一使用qwer1234作为数据库账户口令。

```command
[root@controller ~]# mysql -uroot -pqwer1234
```

```command
MariaDB [(none)]> CREATE DATABASE nova_api;
MariaDB [(none)]> CREATE DATABASE nova;
MariaDB [(none)]> CREATE DATABASE nova_cell0;
MariaDB [(none)]> CREATE USER 'nova'@'localhost' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'nova'@'127.0.0.1' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'nova'@'%' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'localhost';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'127.0.0.1';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'%';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'localhost';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'127.0.0.1';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'%';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'localhost';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'127.0.0.1';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'%';
MariaDB [(none)]> FLUSH PRIVILEGES;
MariaDB [(none)]> EXIT;
```

步骤二：创建Nova身份对象

加载管理员环境，创建nova用户并授予service项目admin角色，然后创建compute服务和三个RegionOne端点。

```command
[root@controller ~]# source /root/admin-openrc
[root@controller ~]# openstack user create --domain default --password qwer1234 nova
[root@controller ~]# openstack role add --project service --user nova admin
[root@controller ~]# openstack service create --name nova --description "OpenStack Compute" compute
[root@controller ~]# openstack endpoint create --region RegionOne compute public http://controller:8774/v2.1
[root@controller ~]# openstack endpoint create --region RegionOne compute internal http://controller:8774/v2.1
[root@controller ~]# openstack endpoint create --region RegionOne compute admin http://controller:8774/v2.1
```

步骤三：安装控制节点软件

教材配套本地软件仓已经作为默认软件源启用，后续直接执行dnf安装命令。

```command
[root@controller ~]# dnf -y install openstack-nova-api openstack-nova-conductor openstack-nova-novncproxy openstack-nova-scheduler
[root@controller ~]# cp -a /etc/nova/nova.conf /etc/nova/nova.conf.bak
[root@controller ~]# vi /etc/nova/nova.conf
```

在nova.conf中写入下列主要参数。所有服务账户和消息账户口令统一为qwer1234。

```config
[DEFAULT]
enabled_apis = osapi_compute,metadata
transport_url = rabbit://openstack:qwer1234@controller
my_ip = 192.168.234.151
use_neutron = true
firewall_driver = nova.virt.firewall.NoopFirewallDriver

[api_database]
connection = mysql+pymysql://nova:qwer1234@127.0.0.1/nova_api

[database]
connection = mysql+pymysql://nova:qwer1234@127.0.0.1/nova

[api]
auth_strategy = keystone

[keystone_authtoken]
www_authenticate_uri = http://controller:5000/
auth_url = http://controller:5000/
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = nova
password = qwer1234

[service_user]
send_service_user_token = true
auth_url = http://controller:5000/v3
auth_strategy = keystone
auth_type = password
project_domain_name = Default
project_name = service
user_domain_name = Default
username = nova
password = qwer1234

[vnc]
enabled = true
server_listen = $my_ip
server_proxyclient_address = $my_ip
novncproxy_base_url = http://controller:6080/vnc_auto.html

[glance]
api_servers = http://controller:9292

[oslo_concurrency]
lock_path = /var/lib/nova/tmp

[placement]
region_name = RegionOne
project_domain_name = Default
project_name = service
auth_type = password
user_domain_name = Default
auth_url = http://controller:5000/v3
username = placement
password = qwer1234

[scheduler]
discover_hosts_in_cells_interval = 300
```

步骤四：同步数据库并建立Cell v2

数据库同步按照API数据库、cell0、cell1和主数据库的顺序执行。

```command
[root@controller ~]# su -s /bin/sh -c "nova-manage api_db sync" nova
[root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 map_cell0" nova
[root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 create_cell --name=cell1 --verbose" nova
[root@controller ~]# su -s /bin/sh -c "nova-manage db sync" nova
```

步骤五：启用Nova控制服务

```command
[root@controller ~]# systemctl enable openstack-nova-api openstack-nova-scheduler openstack-nova-conductor openstack-nova-novncproxy
[root@controller ~]# systemctl start openstack-nova-api
[root@controller ~]# systemctl start openstack-nova-scheduler
[root@controller ~]# systemctl start openstack-nova-conductor
[root@controller ~]# systemctl start openstack-nova-novncproxy
```

步骤六：安装和配置计算节点

在compute安装QEMU、libvirt和nova-compute，备份并编辑配置文件。

```command
[root@compute ~]# dnf -y install qemu libvirt openstack-nova-compute
[root@compute ~]# cp -a /etc/nova/nova.conf /etc/nova/nova.conf.bak
[root@compute ~]# vi /etc/nova/nova.conf
```

```config
[DEFAULT]
state_path = /var/lib/nova

firewall_driver = nova.virt.firewall.NoopFirewallDriver

[api]
auth_strategy = keystone

[keystone_authtoken]
www_authenticate_uri = http://controller:5000/
auth_url = http://controller:5000/
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = nova
password = qwer1234

[service_user]

auth_url = http://controller:5000/v3
auth_strategy = keystone
auth_type = password
project_domain_name = Default
project_name = service

username = nova

project_name = service
auth_type = password
user_domain_name = Default
auth_url = http://controller:5000/v3
username = placement
password = qwer1234

[libvirt]

```

为compute创建稳定身份文件，然后依次启动libvirt和nova-compute。

```command
[root@compute ~]# uuidgen > /etc/nova/compute_id
[root@compute ~]# chown nova:nova /etc/nova/compute_id
[root@compute ~]# chmod 0644 /etc/nova/compute_id
[root@compute ~]# systemctl enable libvirtd openstack-nova-compute
[root@compute ~]# systemctl start libvirtd
[root@compute ~]# systemctl start openstack-nova-compute
```

步骤七：发现计算主机

返回controller，把已经启动的compute加入cell1。至此，Nova控制面、计算面和资源上报关系完成。

```command
[root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 discover_hosts --verbose" nova
```
