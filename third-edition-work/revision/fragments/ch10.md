# 第十章 Neutron的安装及其配置

本章导读：Neutron为OpenStack提供网络即服务能力，把物理网卡、Linux网桥、虚拟端口、子网、路由器和安全组组织成统一网络对象。Nova负责创建实例，Neutron负责把实例接口接入正确网络，并通过DHCP、路由和元数据服务提供地址与通信条件。

本书采用Linux Bridge和ML2插件构建Provider网络与VXLAN租户网络。controller运行Neutron Server及控制类代理，controller和compute都运行Linux Bridge代理；两台主机的ens34不配置IP地址，专门连接外部二层Provider网络。

图10.1表示双节点Neutron组件与网卡的分布。蓝色链路为管理网络，绿色链路为Provider网络，虚线表示VXLAN覆盖网络。

{{FIGURE:图10.1}}

图10.1中，neutron-server集中处理网络对象和API请求，DHCP、L3与Metadata代理在controller创建网络命名空间，Linux Bridge代理分别在两台节点上连接虚拟端口。ens33承担管理和隧道通信，ens34直接映射到provider物理网络。

## 10.1 Neutron功能与网络模型

一．Neutron Server与插件

1．API与数据库

neutron-server是网络服务的控制入口，接收网络、子网、端口、路由器和安全组请求，并把对象状态保存到neutron数据库。它通过Keystone完成身份认证，通过RabbitMQ与各节点代理交换状态和任务。

Neutron控制面只描述逻辑网络，不直接搬运实例数据。实例数据由计算节点网桥、隧道接口、物理网卡和网络命名空间转发，因此API可用与实例通信正常是两个不同层面。

2．ML2与机制驱动

ML2（Modular Layer 2，模块化二层）把网络类型与具体转发机制分开。本书启用flat和VXLAN两种类型，使用Linux Bridge机制驱动。flat网络对应外部二层网络，VXLAN用于不同节点之间的租户网络封装。

ML2配置决定可以创建哪些网络类型、租户默认使用什么网络以及VNI范围。Linux Bridge代理配置决定provider名称映射到哪块物理网卡，并指定VXLAN隧道使用的本地管理地址。

二．网络代理

1．Linux Bridge、DHCP与Metadata

Linux Bridge（Linux网桥）代理在节点上创建网桥和虚拟接口，把实例tap接口接入Neutron端口。DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）代理为子网中的实例分配地址、网关和域名服务器信息。

Metadata代理把实例访问169.254.169.254的请求转交给Nova元数据服务。实例可以通过元数据取得主机名、密钥等初始化信息。Metadata代理与Nova必须使用相同的共享口令，本书统一设置为qwer1234。

2．L3与路由

L3代理负责虚拟路由器、网络地址转换和浮动IP路径。它通常在controller创建路由器命名空间，把租户网络连接到Provider网络。Provider网络本身可以直接承载外部地址，租户网络则通过虚拟路由器访问外部网络。

## 10.2 Provider网络与VXLAN网络

一．Provider网络

1．物理映射

Provider网络把Neutron中的逻辑名称provider映射到ens34。ens34保持无IP地址，由Linux Bridge代理接管并加入网桥。宿主机不通过ens34配置管理地址，可避免宿主网络栈与实例外部网络混在同一接口上。

controller和compute都配置physical_interface_mappings = provider:ens34。这样实例无论被调度到哪一节点，其Provider端口都能进入相同物理二层网络。

2．外部网络路径

实例的Provider网络端口通过tap设备进入Linux网桥，再由ens34进入外部交换网络。该路径不经过VXLAN封装，适合直接使用外部二层地址或承载租户路由器的外部网关。

二．VXLAN租户网络

1．覆盖网络

VXLAN（Virtual Extensible LAN，虚拟扩展局域网）把二层以太网帧封装在三层网络中，使不同计算节点上的实例能够处于同一逻辑网络。封装流量在本书环境中通过ens33管理网络传输，controller使用192.168.234.151，compute使用192.168.234.150作为local_ip。

VNI（VXLAN Network Identifier，VXLAN网络标识符）用于区分不同租户网络。本书把VNI范围设为1:1000，Neutron在该范围内为VXLAN网络分配标识。

MTU（Maximum Transmission Unit，最大传输单元）表示一帧或一个数据包在链路上无需分片即可承载的最大长度。VXLAN会增加封装头部，本书把租户网络MTU设为1450，以便封装后的数据通过1500字节的底层网络。

2．网络命名空间

DHCP和L3代理通过Linux网络命名空间隔离不同网络功能。DHCP命名空间运行dnsmasq，路由器命名空间保存租户路由与网络地址转换规则。命名空间使同一主机能够同时处理多个项目网络而不混淆接口和路由表。

## 10.3 实训项目7 Neutron的手工安装与配置

一．实训前提环境

Nova控制服务和nova-compute已经部署，controller与compute的ens34均处于无IP地址状态。教材配套本地软件仓保持启用，RabbitMQ、Keystone和MariaDB在controller运行。

二．实训涉及节点

controller安装neutron-server、ML2、Linux Bridge、DHCP、L3和Metadata组件；compute只安装Linux Bridge代理。必须先完成controller数据库、身份、配置与服务，再配置compute。

三．实训目标

1．完成neutron数据库、三个来源账户和数据库授权。

2．完成neutron服务用户、admin角色授权、network服务和三个端点创建。

3．完成controller上的Neutron、ML2、Linux Bridge、DHCP、L3和Metadata配置。

4．完成Neutron数据库同步及控制节点服务的顺序启动。

5．完成compute上的Linux Bridge代理配置和服务启动。

四．实训步骤及其详解

步骤一：创建Neutron数据库和账户

```command
[root@controller ~]# mysql -uroot -pqwer1234
```

```command
MariaDB [(none)]> CREATE DATABASE neutron;
MariaDB [(none)]> CREATE USER 'neutron'@'localhost' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'neutron'@'127.0.0.1' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'neutron'@'%' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON neutron.* TO 'neutron'@'localhost';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON neutron.* TO 'neutron'@'127.0.0.1';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON neutron.* TO 'neutron'@'%';
MariaDB [(none)]> FLUSH PRIVILEGES;
MariaDB [(none)]> EXIT;
```

步骤二：创建网络服务身份对象

```command
[root@controller ~]# source /root/admin-openrc
[root@controller ~]# openstack user create --domain default --password qwer1234 neutron
[root@controller ~]# openstack role add --project service --user neutron admin
[root@controller ~]# openstack service create --name neutron --description "OpenStack Networking" network
[root@controller ~]# openstack endpoint create --region RegionOne network public http://controller:9696
[root@controller ~]# openstack endpoint create --region RegionOne network internal http://controller:9696
[root@controller ~]# openstack endpoint create --region RegionOne network admin http://controller:9696
```

步骤三：安装控制节点软件并编辑neutron.conf

```command
[root@controller ~]# dnf -y install openstack-neutron openstack-neutron-ml2 openstack-neutron-linuxbridge ebtables ipset
[root@controller ~]# cp -a /etc/neutron/neutron.conf /etc/neutron/neutron.conf.bak
[root@controller ~]# vi /etc/neutron/neutron.conf
```

```config
[DEFAULT]
core_plugin = ml2
service_plugins = router
transport_url = rabbit://openstack:qwer1234@controller
auth_strategy = keystone
notify_nova_on_port_status_changes = true
notify_nova_on_port_data_changes = true

[database]
connection = mysql+pymysql://neutron:qwer1234@127.0.0.1/neutron

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = neutron
password = qwer1234

[nova]
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
region_name = RegionOne
project_name = service
username = nova
password = qwer1234

[oslo_concurrency]
lock_path = /var/lib/neutron/tmp

[experimental]
linuxbridge = true
```

步骤四：配置ML2和控制节点代理

```command
[root@controller ~]# cp -a /etc/neutron/plugins/ml2/ml2_conf.ini /etc/neutron/plugins/ml2/ml2_conf.ini.bak
[root@controller ~]# vi /etc/neutron/plugins/ml2/ml2_conf.ini
```

```config
[ml2]
type_drivers = flat,vxlan
tenant_network_types = vxlan
mechanism_drivers = linuxbridge,l2population
extension_drivers = port_security

[ml2_type_flat]
flat_networks = provider

[ml2_type_vxlan]
vni_ranges = 1:1000

[securitygroup]
enable_ipset = true
```

```command
[root@controller ~]# vi /etc/neutron/plugins/ml2/linuxbridge_agent.ini
```

```config
[linux_bridge]
physical_interface_mappings = provider:ens34

[vxlan]
enable_vxlan = true
local_ip = 192.168.234.151
l2_population = true

[securitygroup]
enable_security_group = true
firewall_driver = neutron.agent.linux.iptables_firewall.IptablesFirewallDriver
```

```command
[root@controller ~]# vi /etc/neutron/dhcp_agent.ini
```

```config
[DEFAULT]
interface_driver = linuxbridge
dhcp_driver = neutron.agent.linux.dhcp.Dnsmasq
enable_isolated_metadata = true
```

```command
[root@controller ~]# vi /etc/neutron/l3_agent.ini
```

```config
[DEFAULT]
interface_driver = linuxbridge
```

```command
[root@controller ~]# vi /etc/neutron/metadata_agent.ini
```

```config
[DEFAULT]
nova_metadata_host = controller
metadata_proxy_shared_secret = qwer1234
```

步骤五：补充Nova与Neutron联动配置

在controller编辑nova.conf的neutron段，然后重新启动Nova API。

```command
[root@controller ~]# vi /etc/nova/nova.conf
```

```config
[neutron]
auth_url = http://controller:5000
auth_type = password
project_domain_name = Default
user_domain_name = Default
region_name = RegionOne
project_name = service
username = neutron
password = qwer1234
service_metadata_proxy = true
metadata_proxy_shared_secret = qwer1234
```

步骤六：同步数据库并启动控制服务

```command
[root@controller ~]# ln -sf /etc/neutron/plugins/ml2/ml2_conf.ini /etc/neutron/plugin.ini
[root@controller ~]# su -s /bin/sh -c "neutron-db-manage --config-file /etc/neutron/neutron.conf --config-file /etc/neutron/plugins/ml2/ml2_conf.ini upgrade head" neutron
[root@controller ~]# systemctl restart openstack-nova-api
[root@controller ~]# systemctl enable neutron-server neutron-linuxbridge-agent neutron-dhcp-agent neutron-metadata-agent neutron-l3-agent
[root@controller ~]# systemctl start neutron-server
[root@controller ~]# systemctl start neutron-linuxbridge-agent
[root@controller ~]# systemctl start neutron-dhcp-agent
[root@controller ~]# systemctl start neutron-metadata-agent
[root@controller ~]# systemctl start neutron-l3-agent
```

步骤七：配置计算节点Linux Bridge代理

在compute安装代理软件，配置内核转发参数并应用设置。

```command
[root@compute ~]# dnf -y install openstack-neutron-linuxbridge ebtables ipset
[root@compute ~]# vi /etc/sysctl.d/99-openstack-neutron.conf
```

```config
net.ipv4.ip_forward = 1
net.ipv4.conf.all.rp_filter = 0
net.ipv4.conf.default.rp_filter = 0
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
```

```command
[root@compute ~]# sysctl --system
[root@compute ~]# vi /etc/neutron/neutron.conf
```

```config
[DEFAULT]
transport_url = rabbit://openstack:qwer1234@controller
auth_strategy = keystone

[oslo_concurrency]
lock_path = /var/lib/neutron/tmp

[experimental]
linuxbridge = true
```

```command
[root@compute ~]# vi /etc/neutron/plugins/ml2/linuxbridge_agent.ini
```

```config
[linux_bridge]
physical_interface_mappings = provider:ens34

[vxlan]
enable_vxlan = true
local_ip = 192.168.234.150
l2_population = true

[securitygroup]
```

在compute的nova.conf中补充Neutron身份参数，再启用代理并重新启动nova-compute。
