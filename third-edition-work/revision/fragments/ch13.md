# 第十三章 Horizon的安装及云平台初始化

本章导读：Horizon是OpenStack的Web管理界面，它调用Keystone、Glance、Nova、Neutron和Cinder等服务的API，把项目、用户、镜像、实例、网络和卷组织为浏览器中的管理页面。Horizon本身不保存云资源，也不替代各组件服务；页面操作最终仍由相应API执行。

本章先在controller安装和配置Horizon，再使用命令行完成云平台的基础资源初始化。管理员环境用于创建公共资源和租户对象，普通用户环境用于访问所属项目。初始化顺序为身份对象、实例规格、镜像、网络、安全组和密钥对，最后创建实例。

{{FIGURE:图13.1}}

## 13.1 Horizon功能与访问过程

一．Horizon管理界面

1．项目视图与管理员视图

项目视图面向普通云用户，显示当前项目中的实例、网络、镜像、卷和配额。管理员视图增加项目、用户、主机、服务和全局资源管理入口。相同页面是否可见取决于用户角色和服务目录，而不是浏览器本地设置。

2．页面与OpenStack API

Horizon把表单输入转换为API请求。例如创建实例时，页面会读取Glance镜像、Nova实例规格和Neutron网络，再把组合后的请求提交给Nova。页面显示异常时，需要区分Web服务问题、认证问题和后端API问题。

二．会话与缓存

1．登录会话

用户在登录页输入域、用户名和口令，Horizon向Keystone申请令牌，并按令牌所属项目建立会话。会话只保存访问所需状态，实例、镜像和网络等资源仍保存在各自服务中。

2．Memcached缓存

Horizon使用Memcached保存会话和部分缓存数据，减少重复访问。controller已经在第五章安装Memcached，本章只在local_settings中指定缓存地址。实验环境由单个controller提供缓存，生产环境可根据高可用要求部署多个缓存节点。

## 13.2 云平台基础资源

一．身份与资源边界

1．项目、用户和角色

项目是云资源的基本隔离边界，用户通过角色获得项目内权限。管理员先创建项目和用户，再把member角色授予用户。用户登录后只能管理所属项目中的资源，公共镜像和外部网络则由管理员维护。

2．配额与实例规格

配额限制项目可使用的实例数、处理器、内存、网络和存储资源。实例规格描述单台实例的虚拟处理器、内存和根磁盘容量。两者共同决定用户能创建多少实例以及每台实例的资源规模。

二．镜像、网络和访问凭据

1．镜像与网络

镜像提供实例启动所需的系统磁盘内容，网络为实例分配端口和地址。Provider网络直接连接外部二层网络，租户网络通过VXLAN隔离，并经虚拟路由器访问外部网络。

2．安全组与密钥对

安全组是作用于虚拟端口的有状态访问规则，默认通常只允许实例主动发起的通信。密钥对把公钥注入支持cloud-init的镜像，用于远程登录。用户应保存私钥，云平台只保存公钥内容。

## 13.3 请求处理与权限控制

Horizon把多个OpenStack服务的API组织成浏览器页面。用户看到的按钮、表格和向导只是请求入口，真正的身份认证、资源状态和操作结果仍由Keystone、Nova、Glance、Neutron、Cinder和Swift等后端服务决定。理解页面背后的请求路径，可以避免把Horizon误认为独立保存全部云资源的管理系统。

一．登录、会话与服务目录

1．取得作用域令牌

用户在登录页面提交域、用户名、口令和项目范围。Horizon把认证请求发送给Keystone。Keystone验证身份和项目关系后，返回scoped token（作用域令牌，限定用户在某个项目或系统范围内权限的认证结果）以及服务目录。

作用域令牌包含用户、项目、角色和有效期等上下文。Horizon把必要信息保存在服务端会话或配置的会话后端中，浏览器只持有会话标识。使用Memcached保存会话可以避免把大量认证内容写入Web进程内存，也便于多个Web进程共享会话。

认证失败时，Horizon重新显示登录页并说明凭据或作用域不能建立。认证成功却没有目标项目授权时，用户仍不能进入相应项目视图。域、项目、用户和角色属于不同层次，用户名正确不等于已经拥有某个项目的操作权限。

令牌具有有效期。用户持续操作时，Horizon使用当前会话中的认证信息调用后端；令牌过期或会话失效后，需要刷新认证或重新登录。无限延长会话会增加凭据被滥用的风险，过短又会影响长时间管理操作，生产平台应结合安全要求设置会话时长。

2．通过服务目录定位API

服务目录（Service Catalog，记录服务类型、区域和端点的目录）告诉Horizon怎样找到各OpenStack API。Horizon不会把Nova、Glance或Neutron地址逐个硬编码在每个页面中，而是根据服务类型、Region和接口类别选择端点。

例如镜像面板调用image服务端点，实例面板调用compute服务端点，网络面板调用network服务端点。若Keystone中服务或端点缺失，Horizon可能隐藏相应面板，或者在访问时返回无法找到服务。端点地址错误则会表现为连接失败或超时。

本书所有服务都位于RegionOne，public、internal和admin端点在双节点环境中常指向相同主机，但三类端点的语义仍应保留。生产平台可以让外部用户、内部服务和管理员走不同网络入口，Horizon应根据部署配置选择合适接口。

二．面板、策略与后端请求

1．Dashboard、Panel与工作流

Horizon采用可扩展的注册结构。Dashboard（顶层功能区）包含PanelGroup和Panel（面板），面板再组织表格、表单、操作和工作流。项目视图、管理员视图和设置视图由不同Dashboard及其面板组成，第三方项目也可以通过插件增加界面。

面板通过Horizon提供的API封装调用OpenStack客户端库。实例创建向导把多个页面收集的名称、规格、镜像、网络、安全组和密钥对组合成后端请求。向导可以帮助组织输入，却不能跳过Nova、Neutron和Placement各自的检查。

资源列表通常需要多次API调用。例如实例页面先从Nova取得实例，再按需要从Glance取得镜像名称，从Neutron取得网络地址。某个辅助服务暂时不可达时，页面可能只缺少部分显示字段，也可能整体报错，取决于该信息是否属于完成页面所需的必要数据。

2．前端权限与后端策略

Horizon根据作用域令牌中的角色、服务目录和本地策略文件判断面板或按钮是否显示。这层检查改善用户体验，减少用户发出明显无权执行的请求。它不是最终安全边界，因为浏览器界面可以被绕过，用户也可以直接调用API。

后端服务收到请求后，会再次依据自身策略、资源所有权和请求范围判断权限。只有Horizon允许且后端也允许，操作才会成功。若前端策略与后端策略不一致，可能出现按钮可见但操作返回403，或用户实际有权限但界面隐藏功能。

最小权限原则要求只授予完成职责所需的角色和项目范围。管理员视图可以管理跨项目资源，普通项目用户应主要访问本项目对象。为了方便而长期使用admin账户执行所有日常操作，会扩大误操作和凭据泄漏的影响范围。

三．请求结果与异常分支

1．四类常见结果

后端返回成功时，Horizon更新页面或跳转到资源列表。许多云操作是异步的，API成功只表示请求已经接受，资源可能仍处于creating、building或deleting。Horizon需要继续刷新状态，直到资源进入稳定状态或错误状态。

401 Unauthorized表示认证信息无效或令牌已经过期，通常需要重新认证。403 Forbidden表示身份有效，但当前角色、项目或资源所有权不允许该操作。404 Not Found既可能表示对象不存在，也可能是策略为了避免泄露对象存在性而返回的结果。

连接失败、超时或503 Service Unavailable通常说明端点不可达、后端服务停止或上游依赖异常。此时反复刷新浏览器不会修复服务。管理员应根据服务目录定位后端，再检查相应API、消息队列、数据库和组件服务。

表单校验错误通常在请求发出前发现，例如必填字段为空、地址格式错误或数值超出前端允许范围。即使前端校验通过，后端仍会再次校验配额、资源状态和并发条件。前端校验负责尽早提示，后端校验负责维护资源事实。

2．异步状态刷新循环

用户提交创建实例、卷或镜像请求后，Horizon先显示任务已经提交，再按一定间隔重新读取资源状态。资源仍处于中间状态时继续等待；进入稳定成功状态时更新操作按钮；进入ERROR时显示失败状态并保留进一步排查所需的对象ID。

状态刷新应有合理间隔和终止条件。过于频繁会增加API和数据库压力，永不终止的页面轮询会掩盖长期卡住的任务。用户离开页面不会取消后端任务，重新打开资源列表仍可看到实际状态。

3．区域与接口的选择

服务目录中的同一服务可以在不同区域登记端点，每个区域又可以提供公有、内部和管理接口。Horizon根据当前区域、服务类型和接口偏好选择访问地址。若目录中缺少目标区域的端点，相应面板可能无法加载；若端点地址能够解析但网络不可达，页面会在调用服务时出现超时或连接错误。因而，能够登录Keystone不代表所有业务面板都能正常访问。

会话中保存的令牌具有有效期，区域切换或令牌续期后，Horizon需要重新取得相应服务目录。管理员变更端点地址时，还要同时确认DNS、网络、防火墙和Web进程的访问路径。页面展示的是多个后端服务在同一会话中的组合结果，单个面板异常应沿该面板使用的服务类型和端点继续定位，而不是先重启全部OpenStack服务。

四．最小权限与职业伦理

云平台界面把复杂操作集中到少量按钮，也放大了高权限账户误操作的影响。平台管理人员应使用与职责匹配的账户和项目范围，保护口令与会话，不共享管理员身份，不因操作方便而跳过最小权限原则。

资源操作还涉及用户数据、网络边界和业务连续性。查看、导出、删除或调整他人资源必须具有明确授权并保留必要记录。技术人员既要掌握界面和命令，也要尊重数据权属、保护隐私、审慎变更，以可追溯和可恢复的方式履行职业责任。

## 13.4 实训项目10 Horizon安装与云平台初始化

一．实训目标

1．完成Horizon软件包、Web地址、身份服务和缓存参数的配置。

2．启动Apache并通过浏览器访问Dashboard登录页面。

二．安装和配置Horizon

1．安装软件包

在controller从本地软件仓库安装Dashboard软件包。

```command
[root@controller ~]# dnf -y install openstack-dashboard
```

2．编辑Horizon配置

包安装后会生成/etc/openstack-dashboard/local_settings。使用vi打开文件，在末尾添加或修改以下参数；文件中由软件包生成的SECRET_KEY保持原值。

```command
[root@controller ~]# vi /etc/openstack-dashboard/local_settings
```

```command
OPENSTACK_HOST = 'controller'
ALLOWED_HOSTS = ['controller', '192.168.234.151']

SESSION_ENGINE = 'django.contrib.sessions.backends.cache'
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.memcached.PyMemcacheCache',
        'LOCATION': 'controller:11211',
    }
}

OPENSTACK_KEYSTONE_URL = 'http://%s:5000/v3' % OPENSTACK_HOST
OPENSTACK_KEYSTONE_MULTIDOMAIN_SUPPORT = True
OPENSTACK_KEYSTONE_DEFAULT_DOMAIN = 'Default'
OPENSTACK_KEYSTONE_DEFAULT_ROLE = 'member'

OPENSTACK_API_VERSIONS = {
    'identity': 3,
    'image': 2,
    'volume': 3,
}

TIME_ZONE = 'Asia/Shanghai'
WEBROOT = '/dashboard/'
LOGIN_URL = '/dashboard/auth/login/'
LOGOUT_URL = '/dashboard/auth/logout/'
LOGIN_REDIRECT_URL = '/dashboard/'
```

上述参数用于指定身份服务、会话缓存、接口版本、时区和Dashboard访问路径。

3．调整权限并启动Web服务

Horizon由Apache读取local_settings并承载Web请求，因此配置文件既要允许Apache所属用户组读取，又不能向普通用户开放。权限调整完成后重新启动httpd，新的身份服务、缓存和访问路径参数才会进入正在运行的Dashboard进程。

```command
[root@controller ~]# chown root:apache /etc/openstack-dashboard/local_settings
[root@controller ~]# chmod 640 /etc/openstack-dashboard/local_settings
[root@controller ~]# systemctl enable httpd
[root@controller ~]# systemctl restart httpd
```

三．通过浏览器访问Dashboard

1．打开登录页面

在管理主机浏览器中输入http://192.168.234.151/dashboard/，进入登录页面。

登录域填写Default，管理员用户名填写admin，口令填写qwer1234。登录后，概览页面显示当前项目的资源配额和使用情况。用户可以从左侧导航栏进入计算、网络和卷等页面。

2．退出登录

操作结束后使用页面右上角菜单退出登录，浏览器返回登录页面。

五．创建实例规格和镜像

1．创建实例规格

实例规格small包含2个虚拟处理器、2 GiB内存和20 GiB根磁盘。

```command
[root@controller ~]# source /root/admin-openrc
```

2．上传openEuler镜像

配套环境提供openEuler 24.03 LTS SP3的QCOW2（QEMU Copy-On-Write 2，QEMU写时复制第二版）镜像文件。把文件复制到controller的/root目录后执行上传。

```command
[root@controller ~]# ls -lh /root/openEuler-24.03-LTS-SP3-x86_64.qcow2
[root@controller ~]# openstack image create "openEuler-24.03-SP3" --file /root/openEuler-24.03-LTS-SP3-x86_64.qcow2 --disk-format qcow2 --container-format bare --public
```

六．创建网络资源

1．创建Provider网络

本书以192.168.235.0/24作为Provider网络，物理网关为192.168.235.1，可分配地址为192.168.235.100至192.168.235.200。该组参数与虚拟化平台中ens34连接的外部网络相对应。

```command
[root@controller ~]# source /root/admin-openrc
[root@controller ~]# openstack network create --external --share --provider-network-type flat --provider-physical-network provider provider
[root@controller ~]# openstack subnet create --network provider --subnet-range 192.168.235.0/24 --gateway 192.168.235.1 --allocation-pool start=192.168.235.100,end=192.168.235.200 --dns-nameserver 223.5.5.5 provider-subnet
```

2．创建租户网络和路由器

切换到student用户环境，创建10.20.0.0/24租户网络，再创建路由器连接租户网络和Provider网络。

```command
[root@controller ~]# source /root/student-openrc
[root@controller ~]# openstack network create private
[root@controller ~]# openstack subnet create --network private --subnet-range 10.20.0.0/24 --gateway 10.20.0.1 --dns-nameserver 223.5.5.5 private-subnet
[root@controller ~]# openstack router create router1
[root@controller ~]# openstack router add subnet router1 private-subnet
[root@controller ~]# openstack router set router1 --external-gateway provider
```

七．创建访问规则和实例

1．设置安全组并创建密钥对

允许ICMP（Internet Control Message Protocol，互联网控制报文协议）和SSH（Secure Shell，安全外壳协议）进入默认安全组。随后生成student-key密钥对，并把私钥保存为/root/student-key.pem。

```command
[root@controller ~]# source /root/student-openrc
```
