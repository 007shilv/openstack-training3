# 第十一章 Cinder的安装及其配置

本章导读：Cinder为OpenStack提供块存储服务。它把计算节点上的独立磁盘、卷组和逻辑卷组织为可由项目申请的云硬盘，并向Nova提供卷连接信息。实例系统盘可以来自镜像临时生成，也可以放在Cinder卷中长期保存；数据卷则可在实例之间按权限连接和分离。

本书在compute节点使用一块50 GiB独立磁盘/dev/sdb构建LVM后端。controller运行Cinder API和调度服务，compute运行卷服务和LIO目标服务。该结构便于观察控制请求、卷调度与数据通道之间的区别。

图11.1表示Cinder控制面和数据面的分工。控制节点处理身份认证、API请求、调度和卷状态，计算节点使用LVM（Logical Volume Manager，逻辑卷管理器）创建逻辑卷，并通过iSCSI（Internet Small Computer Systems Interface，互联网小型计算机系统接口）向实例提供块设备。

{{FIGURE:图11.1}}

图11.1中，用户请求先到达cinder-api，cinder-scheduler根据后端容量和状态选择cinder-volume。卷服务调用LVM创建逻辑卷，再由LIO（Linux I/O Target，Linux输入输出目标框架）建立目标。实例连接卷时，数据在计算节点与存储后端之间传输，不经过cinder-api。

## 11.1 Cinder功能与组件

一．块存储对象

1．卷、快照与镜像

卷是Cinder管理的基本块设备，可以作为实例的数据盘，也可以保存可启动系统。快照记录卷在某一时刻的状态，可用于创建新卷。镜像与卷之间可以互相转换，但镜像服务管理的是镜像对象，Cinder管理的是可读写块设备，两者的存储语义不同。

2．卷类型与后端

卷类型用于把用户请求映射到特定存储能力。一个云平台可以同时连接LVM、分布式存储和存储阵列，并用卷类型区分性能、可靠性或介质。本书只有一个LVM后端，仍创建名为lvm的卷类型，以建立服务目录、卷类型和后端名称之间的对应关系。

二．Cinder服务组件

1．API与调度服务

cinder-api接收卷的创建、查询、删除和连接请求，并把状态写入数据库。cinder-scheduler根据容量统计、卷类型和过滤规则选择后端。两项服务部署在controller，与Keystone、MariaDB和RabbitMQ共同构成控制面。

2．卷服务与目标服务

cinder-volume部署在持有数据盘的compute节点。它根据配置调用LVM驱动，在cinder-volumes卷组中创建逻辑卷，并通过LIO iSCSI目标驱动公布连接信息。targetclid负责LIO目标配置，因此应先启动targetclid，再启动cinder-volume。

## 11.2 LVM后端与卷访问过程

一．LVM存储结构

1．物理卷与卷组

物理卷PV（Physical Volume，物理卷）把/dev/sdb纳入LVM管理，卷组VG（Volume Group，卷组）把物理卷空间汇集为cinder-volumes。Cinder在卷组中建立逻辑卷LV（Logical Volume，逻辑卷），每个逻辑卷对应一个云硬盘对象。

2．逻辑卷与精简池

LVM后端可以使用精简置备，让逻辑容量按需映射到底层空间。精简置备提高磁盘利用率，但仍需监视实际占用，避免逻辑容量总和远大于物理空间后出现写入失败。实验环境采用单盘结构用于学习对象关系，生产环境通常使用具有冗余、监控和备份能力的共享存储。

二．卷连接过程

图11.2表示实例连接Cinder卷时的主要路径。Nova向Cinder取得连接信息，计算节点根据iSCSI目标信息建立会话，再把块设备交给虚拟机。数据读写由虚拟机、主机内核和存储后端共同完成。

## 11.3 实训项目8 Cinder的手工安装与配置

一．实训目标

1．完成Cinder数据库、服务用户、服务目录和端点的创建。

2．完成controller节点Cinder配置、数据库同步和控制服务启动。

3．确认compute节点/dev/sdb为50 GiB独立数据盘，并建立cinder-volumes卷组。

4．完成compute节点LVM后端、LIO目标服务和cinder-volume服务的配置。

二．创建数据库和身份对象

1．创建数据库

在controller进入MariaDB，创建cinder数据库，并为三个连接来源分别建立同名账户。实验环境统一使用口令qwer1234。

```command
[root@controller ~]# mysql -u root -p
Enter password: qwer1234
MariaDB [(none)]> CREATE DATABASE cinder;
MariaDB [(none)]> CREATE USER 'cinder'@'localhost' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'cinder'@'127.0.0.1' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> CREATE USER 'cinder'@'%' IDENTIFIED BY 'qwer1234';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON cinder.* TO 'cinder'@'localhost';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON cinder.* TO 'cinder'@'127.0.0.1';
MariaDB [(none)]> GRANT ALL PRIVILEGES ON cinder.* TO 'cinder'@'%';
MariaDB [(none)]> FLUSH PRIVILEGES;
MariaDB [(none)]> EXIT;
```

2．创建服务用户、服务和端点

载入管理员环境变量，创建cinder用户，把它加入service项目并授予admin角色。随后创建volumev3服务和RegionOne中的三个端点。

```command
[root@controller ~]# source /root/admin-openrc
[root@controller ~]# openstack user create --domain Default --password qwer1234 cinder
[root@controller ~]# openstack role add --project service --user cinder admin
[root@controller ~]# openstack service create --name cinderv3 --description "OpenStack Block Storage" volumev3
[root@controller ~]# openstack endpoint create --region RegionOne volumev3 public "http://controller:8776/v3/%(project_id)s"
[root@controller ~]# openstack endpoint create --region RegionOne volumev3 internal "http://controller:8776/v3/%(project_id)s"
[root@controller ~]# openstack endpoint create --region RegionOne volumev3 admin "http://controller:8776/v3/%(project_id)s"
```

三．配置controller节点

1．安装软件包并编辑配置

```command
[root@controller ~]# dnf -y install openstack-cinder
[root@controller ~]# vi /etc/cinder/cinder.conf
```

在cinder.conf中写入以下参数。消息队列、数据库和服务用户口令均为qwer1234。

```config
[DEFAULT]
transport_url = rabbit://openstack:qwer1234@controller
auth_strategy = keystone
my_ip = 192.168.234.151

[database]
connection = mysql+pymysql://cinder:qwer1234@127.0.0.1/cinder

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = cinder
password = qwer1234

[oslo_concurrency]
lock_path = /var/lib/cinder/tmp
```

2．同步数据库并启动服务

```command
[root@controller ~]# su -s /bin/sh -c "cinder-manage db sync" cinder
[root@controller ~]# systemctl enable openstack-cinder-api openstack-cinder-scheduler
[root@controller ~]# systemctl start openstack-cinder-api openstack-cinder-scheduler
```

在Nova配置中声明Cinder所在区域，然后重启nova-api使设置生效。

```command
[root@controller ~]# vi /etc/nova/nova.conf
```

```config
[cinder]
os_region_name = RegionOne
```

```command
[root@controller ~]# systemctl restart openstack-nova-api
```

四．配置compute节点存储后端

1．确认并初始化/dev/sdb

先查看块设备、挂载点和LVM信息，确认/dev/sda是系统盘、/dev/sdb是50 GiB独立空白盘、/dev/sdc保留给对象存储。

```command
[root@compute ~]# lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
[root@compute ~]# findmnt -n -o SOURCE /
[root@compute ~]# pvs -o pv_name,vg_name
[root@compute ~]# wipefs --no-act /dev/sdb
[root@compute ~]# blkid -p /dev/sdb
```

只有/dev/sdb确认为50 GiB独立空白盘时，才输入YES并建立物理卷和卷组。

```command
[root@compute ~]# read -p "确认初始化/dev/sdb，输入YES：" ANSWER
[root@compute ~]# test "$ANSWER" = "YES"
[root@compute ~]# pvcreate /dev/sdb
[root@compute ~]# vgcreate cinder-volumes /dev/sdb
```

2．安装软件包并编辑配置

```command
[root@compute ~]# dnf -y install lvm2 device-mapper-persistent-data targetcli openstack-cinder-volume
[root@compute ~]# vi /etc/lvm/lvm.conf
```

在devices段保留系统盘和Cinder数据盘，避免LVM扫描Swift使用的/dev/sdc。

```config
devices {
    filter = [ "a/sda/", "a/sdb/", "r/.*/" ]
}
```

```command
[root@compute ~]# vi /etc/cinder/cinder.conf
```

```config
[DEFAULT]
transport_url = rabbit://openstack:qwer1234@controller
auth_strategy = keystone
my_ip = 192.168.234.150
enabled_backends = lvm
glance_api_servers = http://controller:9292

[database]
connection = mysql+pymysql://cinder:qwer1234@controller/cinder

[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = cinder
password = qwer1234

[lvm]
volume_driver = cinder.volume.drivers.lvm.LVMVolumeDriver
volume_group = cinder-volumes
target_protocol = iscsi
target_helper = lioadm
volume_backend_name = LVM

[oslo_concurrency]
lock_path = /var/lib/cinder/tmp
```

3．启动目标服务和卷服务

```command
[root@compute ~]# systemctl enable targetclid openstack-cinder-volume
[root@compute ~]# systemctl start targetclid
[root@compute ~]# systemctl start openstack-cinder-volume
```

五．创建卷类型

在controller载入管理员环境变量，创建lvm卷类型，并把它与配置中的LVM后端名称关联。

```command
[root@controller ~]# source /root/admin-openrc
[root@controller ~]# openstack volume type create lvm
[root@controller ~]# openstack volume type set --property volume_backend_name=LVM lvm
```
