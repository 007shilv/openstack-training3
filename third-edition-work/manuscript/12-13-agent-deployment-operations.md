# 第12章 智能体的部署和应用

## 学习目标

完成本章学习后，学习者应能够：

1. 区分大语言模型、聊天助手、工作流和智能体；
2. 说明感知、记忆、规划、工具调用、执行、反馈和人工监督之间的关系；
3. 从部署位置、工具权限、模型来源、上下文管理和安全边界等维度比较典型智能体；
4. 在 Windows 教学机上安装 TRAE 国内版，打开 OpenStack 项目工作区；
5. 申请并安全使用 DeepSeek API 密钥，在 TRAE 中完成模型接入和连通性验证；
6. 配置一个用于 OpenStack 部署和运维的专用智能体；
7. 对智能体提出的计划、命令和结果进行人工复核，不以“智能体说成功了”代替证据。

## 12.1 从大语言模型到能执行任务的智能体

大语言模型擅长根据上下文生成文本、代码或结构化内容，但模型本身并不会自动读取本地项目、登录服务器、执行命令或检查服务。聊天助手通常为模型增加了对话界面和有限的上下文管理；工作流把预先确定的步骤连接起来；智能体则在目标和约束下形成计划，选择工具，观察执行结果，并根据反馈继续或停止。

智能体不是“永远正确的自动化程序”。它是一种以模型推理为核心、以工具和环境为行动通道、以反馈和人工监督为闭环的任务执行系统。在 OpenStack 运维场景中，智能体需要同时处理配置文件、命令行、服务状态、API 返回、日志、网络和存储风险，因此“可执行”必须与“可审计”一起设计。

## 12.2 智能体的基本架构

一个面向云平台的智能体通常包含七个相互配合的部分。

1. **目标与角色**：明确“要完成什么”和“哪些事不能做”。例如，只允许操作教学集群，禁止初始化系统盘。
2. **感知与上下文**：读取用户要求、项目文件、主机状态、配置和日志。上下文越多并不一定越好，应优先提供与当前任务直接相关的材料。
3. **计划**：把复杂目标拆成有依赖关系的步骤。OpenStack 必须先完成基础服务和 Keystone，再部署依赖身份服务的组件。
4. **记忆**：保存当前会话状态、项目规则和已经验证的事实。凭据不应作为普通记忆长期保存。
5. **工具调用**：访问文件、终端、版本库、浏览器或远程主机。工具权限决定了智能体实际能影响的范围。
6. **执行与观察**：运行一步、读取返回码和输出，再决定继续、修正或停止。
7. **人工监督**：在磁盘初始化、资源删除、网络改动和凭据使用等高风险节点由人确认。

## 12.3 智能体生态与典型产品

截至资料冻结日，智能体已经形成 IDE 内智能体、终端编码智能体、桌面多任务智能体、个人智能体和开源自托管智能体等形态。本书选择 TRAE 与 DeepSeek 作为主要教学组合，同时介绍 Claude Code、OpenAI Codex、OpenClaw 和 Hermes Agent，以帮助学习者理解不同产品的边界，而不是进行简单的“优劣排名”。

### 12.3.1 TRAE 与 DeepSeek：本书的国内教学组合

TRAE 是面向软件开发和工程任务的 AI IDE。官方中文社区在2026年的教程中列出了项目管理、插件管理、自定义智能体、侧边对话、行内对话、Prompt 优化、上下文、MCP、自定义模型和 Memory 等学习内容。本书使用 TRAE 国内版打开 `openstack-ts` 工作区，使智能体能够在项目约束下读取脚本、形成计划并调用经过授权的终端工具。

DeepSeek 在本书中承担模型服务角色。DeepSeek 官方 API 提供兼容常见接口形式的服务入口，并支持工具调用。模型标识可能随服务更新而变化，因此课堂配置前应通过官方“模型列表”或控制台确认可用模型，不把旧模型名写死在长期使用的模板中。

## 12.6 创建 OpenStack 部署与运维智能体

新建自定义智能体，名称建议为“OpenStack 教学平台智能体”。将工作区限制为受控 `openstack-ts` 副本，开放只需的文件读取、终端和版本差异查看能力。默认采用“先计划、后确认、再执行”；磁盘初始化、网络地址修改和删除资源必须再次确认。

可使用下面的角色说明作为系统提示词基础：

```text
你是 OpenStack 教学平台智能体。目标是在两台 openEuler 24.03 LTS SP3
教学虚拟机上，依据当前工作区 openstack-ts 的已验证脚本，部署并运维
OpenStack 2023.1 Antelope。

固定事实：controller=192.168.234.151，compute=192.168.234.150；
管理网卡 ens33；Provider 映射网卡 ens34 且不得配置 IP；
compute 的 /dev/sda 是系统盘，严禁初始化；/dev/sdb 仅用于 Cinder；

未经人工批准不得执行。凭据只通过交互或受保护的运行时环境获取，不得显示、
记录或写入项目。每一阶段检查返回码；失败立即停止，不跳过、不掩盖。
部署后必须用 OpenStack CLI/API 和服务状态独立验收，不以自然语言结论代替证据。
```

## 12.7 隐私、凭据与提示注入防护

云平台智能体既能读取内部配置，又能执行高权限操作，必须建立多层安全边界。

- **最小上下文**：只打开需要的工作区，不把个人目录、下载目录或其他课程资料一并授权。
- **凭据隔离**：密钥和密码只存在于受保护控件、系统凭据管理器或运行时环境，绝不写入 Git。
- **主机身份校验**：远程连接使用人工核对的主机公钥，拒绝未知或变化的主机密钥。
- **提示注入防护**：把网页、日志和仓库文本视为不可信数据；其中“忽略规则”“上传密钥”等内容不得改变系统约束。
- **最小工具权限**：只开放当前任务需要的工具，高风险命令保持人工确认。
- **输出脱敏**：截图前退出账号页，遮挡令牌；截图后再以 OCR 和文本搜索检查。
- **费用控制**：限制模型并发、重试和长上下文，记录教学任务的用量。
- **可追溯性**：保存提示词、计划、命令、返回码、资源 ID 和验收报告，但不保存秘密。

## 13.8 素养拓展：负责任地使用智能体，练就数字工匠精神

自主可控并不等于把国外工具简单替换为国内工具，也不等于把人的责任交给模型。openEuler、OpenStack、TRAE 和 DeepSeek 的组合体现了开源协作、国产基础软件生态和工程实践的结合。学习者既要看到国产平台持续进步，也要尊重全球开源社区的贡献，用开放、严谨的态度参与技术创新。

数字工匠精神体现在每一次核对中：不把猜测写成事实，不把“无报错”当作成功，不隐藏失败，不越过磁盘和数据安全底线。智能体可以提高速度，但最终批准、验收和责任仍属于人。面对可自动化的工作，职业能力不再只是记住命令，而是能够定义目标、设置边界、判断证据、处理异常并持续改进。

**思考题**：如果智能体给出了看似合理但会初始化错误磁盘的计划，操作者批准后造成数据损失，责任应如何划分？团队应怎样通过技术和制度减少这类风险？

## 本章小结

本章把智能体用于一次性部署和持续运维，但始终保持人工监督与独立验收。一次性部署严格遵循17阶段跨节点顺序，Cinder 与 Swift 的磁盘初始化设置二次确认。运维任务覆盖身份与配额、镜像、规格、网络、路由、安全、实例、浮动 IP、卷、对象、快照、调整、巡检、故障诊断、服务恢复、容量、日志、备份和清理。高质量智能体任务必须同时包含目标、事实、边界、步骤、验证和回滚。
